# Structure

## Top-Level Layout

- `pyproject.toml` — root Python project manifest managed by uv.
- `backend/` — FastAPI backend and exported Python requirements.
- `frontend/` — Vite React application.
- `data/` — local seed metadata for Dexter.
- `index.html` — standalone static landing/prototype page.
- `main.py` — default PyCharm sample script; not connected to the app.
- `.env.example` — example Neo4j environment variables.
- `.gitignore` — ignores Python, Node, Neo4j local runtime files, IDE files, and secrets.
- `neo4j_data/` and `neo4j_logs/` — local Neo4j runtime directories, ignored by git but present in the working tree.

## Backend Layout

- `backend/requirements.txt` — uv-exported pinned requirements with hashes.
- `backend/app/__init__.py` — package marker.
- `backend/app/main.py` — FastAPI app, lifespan, CORS, health route, router inclusion.
- `backend/app/api/__init__.py` — API package marker.
- `backend/app/api/series.py` — `/api/series` routes.
- `backend/app/core/__init__.py` — core package marker.
- `backend/app/core/config.py` — settings model and cached settings accessor.
- `backend/app/domain/__init__.py` — domain package marker.
- `backend/app/domain/series.py` — Pydantic response models.
- `backend/app/graph/__init__.py` — graph package marker.
- `backend/app/graph/database.py` — Neo4j driver wrapper/global instance.
- `backend/app/graph/seed.py` — graph seed script.
- `backend/app/revisions/__init__.py` and `backend/app/spoiler/__init__.py` — empty package placeholders for future features.

## Frontend Layout

- `frontend/package.json` — npm scripts and dependencies.
- `frontend/package-lock.json` — npm lockfile.
- `frontend/vite.config.ts` — Vite React plugin config.
- `frontend/tsconfig.json`, `frontend/tsconfig.app.json`, `frontend/tsconfig.node.json` — TypeScript project config.
- `frontend/eslint.config.js` — ESLint flat config.
- `frontend/index.html` — Vite HTML entry for the React app.
- `frontend/src/main.tsx` — React root entry point.
- `frontend/src/App.tsx` — root React component.
- `frontend/src/index.css` — global starter theme/layout.
- `frontend/src/App.css` — component-level starter styles.
- `frontend/src/assets/` — local React/Vite/hero assets.

## Data Layout

- `data/dexter/metadata/series.json` — series metadata.
- `data/dexter/metadata/episodes.json` — episode metadata.

`backend/app/graph/seed.py` derives `PROJECT_ROOT` from its file path and expects this exact `data/dexter/metadata/` location.

## Planning Layout

- `.planning/` already exists from GSD setup.
- `.planning/codebase/` is generated by the codebase mapping workflow.

## Naming Conventions Observed

- Python packages use lowercase directory names.
- Pydantic response models use `PascalCase` names ending in `Response`.
- API router functions use action nouns: `list_series`, `list_episodes`.
- Neo4j labels use `PascalCase`: `Series`, `Episode`.
- Neo4j relationship types use uppercase verbs: `PART_OF`, `PRECEDES`.
- JSON metadata IDs use lowercase snake/episode codes, e.g. `series_dexter`, `dexter_s01e01`.
