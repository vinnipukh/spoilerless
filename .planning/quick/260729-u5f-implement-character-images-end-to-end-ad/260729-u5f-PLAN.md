# Quick Task Plan: Character images end-to-end

## Objective

Add optional `image_url`/`image_source_url` to `Character` nodes, surfaced in the
graph payload, Cytoscape node backgrounds, and the detail panel portrait —
without touching spoiler filtering, node identity, or existing API contracts.

## Task 1: Backend — optional image fields on GraphNode

**Files:** `backend/app/domain/graph.py`, `backend/app/spoiler/filter.py`

1. Add `image_url: str | None = None` and `image_source_url: str | None = None`
   to `GraphNode`.
2. Extend `NODES_QUERY` to return `node.image_url` / `node.image_source_url`.
   The query is shared by all node types (Character, Event, Location, ...) —
   non-Character nodes simply have the property absent in Neo4j, which reads
   back as `null`.
3. No seed-loader code change needed: `_upsert_nodes` already does
   `MERGE ... SET node += row`, so adding (or omitting) `image_url` keys in
   `data/dexter/seed/characters.json` rows is idempotent by construction.

## Task 2: Frontend types + Cytoscape rendering

**Files:** `frontend/src/types/graph.ts`, `graphElements.ts`, `graphStylesheet.ts`

1. Mirror the two new fields on the `GraphNode` TS type.
2. In `graphToElements`, set a Cytoscape `imageUrl` data key **only** for
   `Character` nodes that have a non-null `image_url` (key omitted, not set to
   null, so the stylesheet's `[imageUrl]` existence selector can't false-match).
3. Add a stylesheet rule `node[nodeType = "Character"][imageUrl]` with
   `background-image: data(imageUrl)`, `background-fit: cover`,
   `background-clip: node` — Cytoscape draws to canvas, so a failed image load
   degrades to the existing flat background-color fill; no broken-image DOM
   node is possible.

## Task 3: Detail panel portrait

**File:** `frontend/src/components/detail/DetailPanel.tsx`

1. Add a `CharacterPortrait` subcomponent: renders an `<img>` when
   `image_url` exists and hasn't errored, else an initials avatar
   (`useState` + `onError` fallback, keyed by node id so state doesn't leak
   between selections).
2. Wrap the avatar in an `<a target="_blank" rel="noopener noreferrer">` when
   `image_source_url` exists.
3. Render `CharacterPortrait` in `SheetHeader` next to the title, only for
   `selectedNode?.type === 'Character'`.

## Task 4: Tests

1. Backend: model-level tests for optional/explicit image fields
   (`test_graph_api.py`), plus a live-DB test asserting `image_url` /
   `image_source_url` keys are present (null) on every graph node.
2. Frontend: fixture nodes updated with the two new fields (one seeded
   example on `char_dexter_morgan` to exercise the "has image" path);
   `graphElements.test.ts` covers the imageUrl mapping rules; `DetailPanel.test.tsx`
   covers portrait+link, initials fallback, image-load-failure fallback, and
   no-portrait-for-non-Character.

## Task 5: Image mappings

Attempted to fetch real portrait URLs from `dexter.fandom.com` (WebFetch,
Chrome extension, direct `curl`) — all blocked (WebFetch 402, no Chrome
extension connected, Fandom's Cloudflare JS challenge blocks `curl`). Per the
task's explicit instruction not to invent mappings when uncertain, no
`image_url`/`image_source_url` values are seeded this pass; all 9 Dexter
S01E01–03 characters stay unmapped (both fields `null`). The feature is fully
wired so mappings can be added later by editing
`data/dexter/seed/characters.json` and re-running the seed.
