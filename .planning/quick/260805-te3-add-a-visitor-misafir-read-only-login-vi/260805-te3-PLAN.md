# Quick Task 260805-te3: Visitor (Misafir) Read-Only Login

## Background (verified 2026-08-05)

- Backend ALREADY enforces view-only for anonymous users: every write route
  (`user_content.py`, `progress.py`, `change_set.py`, `chat.py`, `revisions.py`,
  `candidates.py`) is gated by `CurrentUserDependency` → 401 without a session
  (09-03, commit `0f3c388`). All read routes (`graph.py` GET graph, POST path,
  GET export; `series.py`) are anonymous. **Zero backend changes needed.**
- Frontend currently hard-gates the whole app behind Google auth:
  `App.tsx:609` → `unauthenticated | error` renders `LoginPage`; the app is
  unreachable without a Google account.
- Existing read-only precedent: FEAT-09 `GraphCanvas readOnly` prop (share view)
  hides the create-node FAB + share-link affordances.

## Task 1 — Auth plumbing: visitor state + entry point

Files:
- `frontend/src/providers/AuthContext.ts`
- `frontend/src/providers/AuthProvider.tsx`
- `frontend/src/components/auth/LoginPage.tsx`
- `frontend/src/components/layout/AppShell.tsx`

Action:
- `AuthContext.ts`: add `{ status: 'visitor' }` to `AuthState`; add
  `enterVisitor: () => void` to `AuthContextValue`.
- `AuthProvider.tsx`: implement `enterVisitor` (set `visitor` state + persist
  `sessionStorage['spoilerless.visitor']='1'`). Mount hydration: after `/me`
  returns AUTH_UNAUTHENTICATED, if the sessionStorage flag is set → `visitor`
  (a 200 `/me` always wins → authenticated). `logout` clears the flag.
- `LoginPage.tsx`: "Continue as visitor" outline button under the Google button
  → `enterVisitor()`. Copy: "Continue as visitor" + subtitle
  "Browse the graph without an account — read-only".
- `AppShell.tsx`: optional `visitor?: boolean` + `onSignIn?: () => void` props;
  when visitor, render a muted "Visitor" badge + "Sign in" button (calls
  `logout` → back to LoginPage).

Verify: `NODE_ENV=test CI=1 npx vitest run src/App.test.tsx -t "visitor"` green;
`npm run build` green.

## Task 2 — Read-only enforcement in the app

Files:
- `frontend/src/hooks/useWatchProgress.ts`
- `frontend/src/App.tsx`
- `frontend/src/components/detail/DetailPanel.tsx`
- `frontend/src/components/palette/CommandPalette.tsx`

Action:
- `useWatchProgress({ persist })` (default true): when `persist === false` —
  skip mount hydration GET, `requestChange` always applies the order LOCALLY
  (`seriesId` + `viewAsOfOrder`, never a POST, never `pendingChange`/modal),
  `confirmChange` no-ops. Visitor browsing stays purely local; the anonymous
  graph GET already serves any boundary.
- `App.tsx`: `isVisitor = state.status === 'visitor'`;
  `useWatchProgress({ persist: !isVisitor })`; visitor auto-seed effect (when
  visitor + no seriesId + series list loaded → select first series at order 1);
  GraphCanvas `readOnly={isVisitor}` + `onShareLink` undefined for visitor;
  hide `ChatLauncher` + `ChatSheet` for visitor (chat = auth-gated writes +
  LLM cost); `CommandPalette onOpenChat` optional → hide the chat row for
  visitor; `AppShell visitor={isVisitor} onSignIn={logout}`.
- `DetailPanel.tsx`: optional `readOnly` prop — hides Create Relationship
  button/dialog and the Add Note form + note edit/delete actions.
- `CommandPalette.tsx`: `onOpenChat?: () => void` — render the chat action row
  only when provided.

Verify: `npm run build` green; focused vitest on `useWatchProgress`,
`App.test.tsx -t visitor`, `DetailPanel.test.tsx -t readOnly` (pre-existing
reds in DetailPanel/App suites are sibling in-flight work — do not add new
failures).
