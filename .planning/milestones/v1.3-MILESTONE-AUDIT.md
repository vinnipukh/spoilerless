## 2. Cross-Phase Integration

### 2.1 Spoiler policy resolver — shared across channels (VERIFIED)

One pure fail-closed resolver: `spoilerless/app/spoiler/policy.py::resolve_effective_boundary`
= `min(requested_view_order, watched_progress)`, None-progress fails closed to order 1.
Consumed by the projection service (`services/visualization.py:196`) and by every
`api/graph.py` route through `_resolve_effective_boundary`/`effective_view_order`:
graph GET (:138), visualization (:226), expand (:349), path (:488), export (:521).
The policy docstring names graph reads, projection, expansion, path/search, GraphRAG
focus, and saved restoration as the single-resolver channels. Cache keys are re-validated
against the effective order. **Seam intact.**

### 2.2 Cache epoch contract (VERIFIED)

`spoilerless/app/cache/graph_cache.py`: per-series Redis epoch `graph_revision`
(`EPOCH_KEY_PREFIX`, default 0), read at cache-read/write time; cache keys carry
`series / effective order / view / projection_version / epoch / user scope / focus-SHA256`.
`invalidate_series()` bumps the epoch atomically BEFORE deleting (a racing projection
write lands on the old-epoch key and is never served, D-30) and is called on every
graph-mutating write: change-set confirm/reject, candidate approve/reject/edit, and all
six user-content create/update/delete paths. Expansion is deliberately uncached
(T10-CACHE-06). **Seam intact.**

### 2.3 Frontend route calls — GAP-1 (BLOCKER-class integration gap) — **CLOSED 2026-08-14**

**Original finding (verified at HEAD cdef4bb):** the production frontend never called
the Phase-10 backend routes — `fetchVisualization`/`fetchExpansion` had zero callers,
the `visualization` prop was test-only, the four-tab hierarchy was navigation-only,
no expansion UI existed, and AnswerGraph was presentation-only. VIZ-01/06/07/08 were
implemented + unit-tested but not wired end-to-end. Spoiler safety held (legacy route
boundary filtering), so it was an integration gap, not a leak.

**Closure (commit `b133ee7`, 260814-viz):**
- `App.tsx` now maps tabs → projection views and fetches them:
  **Characters → `character_network`**, **Evidence → `investigation`**,
  **Answer Graph → `graphrag_focus`** (focus ids from the chat citation), with
  abort-cancelled effects keyed on view/series/boundary; Story + Advanced keep the
  legacy `GraphResponse` scene deliberately (user content — custom nodes/edges —
  exists only there, never in projection DTOs).
- Semantic expansion UI: "Expand {node}" menu with the 7 allowlisted keys wired to
  `fetchExpansion`; delta DTOs merged into the base scene (dedup by id) and passed
  through the `visualization` prop; Undo-last + Collapse-per-anchor wired to the
  reducer history actions; 44px targets, no new dependencies.
- `GraphCanvas` `visualization` prop semantics extended: `undefined` = explicit
  leave-projection (clears the DTO hold, legacy scene restored); `null` = loading
  retain (D-44 unchanged).
- Verified: `App.test.tsx` 31/31 (3 new wiring tests: tab→view fetch, expansion
  flow incl. Undo, graphrag_focus fetch), full frontend suite **400 passed**, tsc/vite
  build clean, backend offline suites **130 passed** (projection/baseline/cache/
  graphrag/coverage/runner guards).
