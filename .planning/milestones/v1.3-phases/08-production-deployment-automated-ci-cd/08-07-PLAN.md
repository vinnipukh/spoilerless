  <read_first>backend/app/core/errors.py, backend/app/main.py</read_first>
  <files>backend/app/core/errors.py, backend/app/main.py, backend/tests/test_error_handlers.py</files>
  <behavior>
    - Test: triggering the ConstraintError handler logs an ERROR-level record containing the exception's type name (assert via pytest's caplog fixture) before the 409 response is returned; the response body is unchanged from today.
    - Test: triggering the database_handler (ServiceUnavailable/AuthError/ClientError/Neo4jError/OSError) logs an ERROR-level record with exc_info before the 503 response is returned.
    - Test: triggering the RequestValidationError handler logs before the 422 response is returned.
    - Test: a request-logging middleware log line never contains the literal value of an X-LLM-Api-Key header or the session cookie's raw token value, even when both are present on the request.
  </behavior>
  <action>
    In backend/app/core/errors.py, add `import logging` and `logger =
    logging.getLogger(__name__)` near the top. In each of
    `constraint_handler`, `database_handler`, and `validation_handler`
    inside `install_error_handlers`, add `logger.error("<handler-name>_error",
    exc_info=exc)` (or `exc_info=_exc` for the constraint/validation
    handlers whose exception parameter is currently named with a leading
    underscore — rename it to a used parameter now that it is logged)
    immediately before building and returning the sanitized response. This
    is the exact "log before sanitize" pattern 08-RESEARCH.md's Pattern 4
    documents.

    In backend/app/main.py, add a request-logging middleware (a plain
    `@app.middleware("http")` async function, or `BaseHTTPMiddleware`) that
    logs one INFO-level line per request with method, path, status code, and
    duration in milliseconds. It MUST NOT log the request body, the full
    header dict, the `Cookie` header, or the `X-LLM-Api-Key` /
    `X-LLM-Base-URL` / `X-LLM-Model` headers the BYOK plan (08-02) added —
    if the middleware logs headers at all for debugging, explicitly build an
    allowlist of safe header names (e.g. `User-Agent`, `Content-Type`) and
    log only those, never the full header dict and never any header whose
    name matches `X-LLM-*` or `Cookie`/`Set-Cookie`.
  </action>

  </verify>

    - Full backend suite remains green
