<objective>
Close the two remaining gaps in `verify_origin`'s CSRF defense and make the
session cookie's `SameSite` policy settings-driven: stop auto-allowing
requests with neither `Origin` nor `Referer` present, and add the same CSRF
dependency to `POST /api/auth/logout`, which currently has none at all
(docs/PROBLEMS.md #10).

Purpose: A cookie-authenticated state-changing request without any
Origin/Referer information is no longer trusted by default; logout can no
longer be triggered cross-site without consent.
Output: verify_origin fails closed on missing Origin/Referer; logout is
CSRF-protected; SameSite is configurable per environment.
</objective>

  <action>
    In backend/app/core/config.py, add `session_cookie_samesite: str =
    Field(default="lax", description="SameSite policy for the session
    cookie. 'lax' is correct when frontend and backend share a registrable
    root domain via custom subdomains (D-10); set 'none' only if ever
    falling back to fully cross-site default platform domains, and pair
    that with Secure=true.")`.

    In backend/app/api/auth.py, change `verify_origin`'s final branch: where
    the docstring today says "If neither Origin nor Referer is present,
    allow the request through," replace the `if candidate is None: return`
    early-return with raising the same `AUTH_ORIGIN_NOT_ALLOWED` 403 the
    function already raises for a non-matching origin — the missing-header
    case is no longer treated differently from a mismatched one. Keep the
    existing wildcard escape hatch (`if "*" in origins: return`) exactly as
    is; it remains the explicit, intentional way to disable this check.
    Update the function's docstring to describe the new fail-closed
    behavior instead of the old fail-open one.

    Add `_csrf: Annotated[None, Depends(verify_origin)]` as a parameter to
    the `logout` route, in the same position `google_auth` already declares
    it, so logout gets the identical CSRF dependency chain.

    Change `_make_cookie`'s and `_delete_cookie`'s hardcoded
    `samesite="lax"` to `samesite=get_settings().session_cookie_samesite`
    (or thread it as an explicit parameter from the call sites, matching how
    `secure` is already threaded — prefer the explicit-parameter form for
    consistency with the existing function signatures).

    Update backend/tests/test_auth.py: every existing test that calls
    `POST /api/auth/google` or (once this lands) `POST /api/auth/logout`

    file for TestClient calls to these two routes and add the header where
