<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Repo working tree <-> git history | Renames must never rewrite history (D-12); only working-tree changes |
| Browser localStorage <-> app code | Storage-key rename can silently orphan existing user settings |
| render.yaml <-> live Render service | Blueprint name change may provision a new service (A5) — operator dashboard action deferred to 09-16 |
| Python import root <-> runtime entry points | Every uvicorn/console/CI entry that references the old module path breaks if swept incompletely |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-09-01-01 | Tampering | Import-root rename (every `backend.app.*` reference) | high | mitigate | `git mv` + mechanical sed-class sweep + full backend pytest gate on scratch Neo4j; `git grep -n 'backend.app'` zero-hit verify |
| T-09-01-02 | Information Disclosure | localStorage BYOK key rename | medium | mitigate | read-compat migration reads the old key once; delete old key only after a successful new-key save |
| T-09-01-03 | Spoofing | /health service-field drift between code and test | low | mitigate | SERVICE_NAME constant + test assertion updated in the same plan (test_graph_api.py) |
| T-09-01-04 | Denial of Service | Incomplete sweep leaves a broken deploy (startCommand/module path) | high | mitigate | render.yaml + ci.yml + smoke.sh all swept in Task 1/2; `uv sync` + suite gate before commit |
| T-09-01-SC | Tampering | npm/pip/cargo installs | high | mitigate | No new dependencies in this plan (zero-cost constraint); `uv sync` only re-resolves existing pinned deps |
</threat_model>
