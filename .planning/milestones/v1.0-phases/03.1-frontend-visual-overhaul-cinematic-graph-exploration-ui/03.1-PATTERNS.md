## Pattern Assignments

### `frontend/src/index.css` (config, transform)

**Analog:** itself — extend the existing token block, do not restructure it.

**Fontsource import pattern** (line 4) to mirror for the two new fonts:
```css
@import "@fontsource-variable/geist";
```
becomes two imports (`@fontsource-variable/space-grotesk`, `@fontsource-variable/inter`), and the `@theme inline` block's font vars (lines 9-10):
```css
--font-heading: var(--font-sans);
--font-sans: 'Geist Variable', sans-serif;
```
should split into a real `--font-heading` (Space Grotesk Variable, with a system fallback stack) and `--font-sans` (Inter Variable, with a system fallback stack) — no longer aliasing heading to body.

**Token block pattern** (lines 61-97, `:root`) — CSS custom properties, flat hex/rgba values, one block for `:root` and an identical mirrored `.dark` block (lines 99-133). New/adjusted tokens (grid/glow surface colors, any new chart/edge-family colors) must be added as additional `--name: value;` lines in *both* blocks, keeping them in sync — do not add a token to only one.

**Tailwind v4 `@theme inline` mapping pattern** (lines 8-52) — every semantic CSS var gets a matching `--color-x: var(--x);` (or `--radius-x: calc(...)`) line inside `@theme inline` so Tailwind utility classes (`bg-background`, `text-muted-foreground`, etc.) resolve. Any new token intended for use via a Tailwind utility class must get a corresponding `@theme inline` line, not just a raw `:root` var.

### `frontend/src/components/graph/graphStylesheet.ts` (config, transform)

**Analog:** itself.

**Header-comment convention** (lines 1-13) — every non-obvious selector or design decision gets a comment referencing the prior phase's research/pitfall numbers or a design-doc gate. New selectors (type-aware sizing, edge-color-by-relationship-type) should keep this convention, citing `03.1-CONTEXT.md` decision IDs (e.g. `// D-19`, `// D-28`) instead of `02-RESEARCH.md` ones.

**Node sizing pattern to replace** (lines 17-18, 33-34, 92):
```typescript
const NODE_SIZE = 36
const SERIES_NODE_SIZE = 46
...
width: NODE_SIZE,
height: NODE_SIZE,
...
{ shape: 'star', width: SERIES_NODE_SIZE, height: SERIES_NODE_SIZE },
```
This flat-constant approach is the exact site D-19 requires changing to type-aware sizing — keep the same "per-node-type selector overrides a shared base style" mechanism (selector array of `{ selector, style }` objects), just parameterize width/height per `nodeType` selector the same way shape is already parameterized.

**Node-type shape mapping pattern** (lines 44-93) — one `{ selector: 'node[nodeType = "X"]', style: {...} }` entry per real type, in the same order as D-09's real type list. New color-fill rules should be added as additional `style` keys on these same selector blocks (e.g. add `'background-color'` next to `shape`), not as new selector entries, to keep one authoritative rule per type per D-15.

**Origin border treatment** (lines 94-98) — must remain last-applied/highest-specificity relative to base node style so D-25's solid-vs-dashed distinction survives new color fills; don't reorder this above the per-type blocks.

**Selection/fade class pattern** (lines 99-138, `selected-dominant`/`faded`/`edge-active`) — this is Pattern 3 from `02-PATTERNS.md`; extend the existing `node.selected-dominant`/`node.faded`/`edge.hovered, edge.edge-active`/`edge.faded` selector blocks with additional style properties (glow via `shadow-blur`/`shadow-color` Cytoscape properties, thicker edge width) rather than adding new class names — D-26 says extend, don't replace the class contract.

**Edge base style to extend for D-28 (relationship-type coloring)** (lines 112-126):
```typescript
{
  selector: 'edge',
  style: {
    label: 'data(label)',
    'font-size': 9,
    color: '#94A3B8',
    width: 1.5,
    'line-color': 'rgba(255, 255, 255, 0.08)',
    'target-arrow-color': 'rgba(255, 255, 255, 0.08)',
    'target-arrow-shape': 'triangle',
    'curve-style': 'bezier',
    ...
  },
},
```
New per-relationship-type color selectors should follow the exact `edge[edgeType = "X"]` selector form (mirroring the node-type selectors above), each setting both `'line-color'` and `'target-arrow-color'` together (never one without the other — the file already keeps these two properties paired everywhere, e.g. line 130-131 for hover/active state) and should live in `relationshipStyles.ts`, imported and spread into this stylesheet array (see next section) per D-15's single-source-of-truth mandate.

### `frontend/src/components/graph/GraphCanvas.tsx` (component, event-driven)

**Analog:** itself.

**Module-scope extension registration + fallback pattern** (lines 9-29) — mandatory template for any new Cytoscape extension (only if research justifies replacing `cose-bilkent`, per D-18):
```typescript
let layoutName: 'cose-bilkent' | 'cose' = 'cose-bilkent'
try {
  cytoscape.use(coseBilkent)
} catch (error) {
  console.error('...', error)
  layoutName = 'cose'
}
```
Reuse verbatim (renaming the union type) if `fCoSE` is ever added as a third option — this is the exact fallback CONTEXT.md's "Reusable Assets" section calls out as reusable.

**Memoization pattern (D-21, mandatory to preserve)** (line 86):
```typescript
const elements = useMemo(() => graphToElements(graph), [graph])
```
Any new derived-data computation (e.g. a memoized node/edge style-class lookup) must follow this exact `useMemo(..., [graph])` shape — never inline-compute inside the render body or inside the `cy` callback.

**Ref-guarded listener wiring pattern (D-35, mandatory to preserve)** (lines 93-94, 111-172):
```typescript
const wiredCyRef = useRef<cytoscape.Core | null>(null)
const cyInstanceRef = useRef<cytoscape.Core | null>(null)
...
cy={(cy) => {
  cyInstanceRef.current = cy
  if (wiredCyRef.current === cy) return
  wiredCyRef.current = cy
  cy.on('mouseover', 'node', (evt) => { ... })
  ...
}}
```
D-27's new "hover a node → brighten its connected edges" behavior must be added as an additional `cy.on('mouseover'/'mouseout', 'node', ...)` pair inside this same guarded block (alongside the existing `mouseover`/`mouseout` node/edge handlers at lines 121-132), using `node.connectedEdges().addClass('hovered')` / `removeClass('hovered')` — reuse the existing `hovered` class already styled at line 128, do not invent a new class name. Must NOT call `onSelect(...)` from a hover handler (D-27: hover ≠ selection).

**Layout re-run effect pattern (D-21, mandatory to preserve)** (lines 99-103):
```typescript
useEffect(() => {
  const cy = cyInstanceRef.current
  if (!cy) return
  runLayout(cy)
}, [graph])
```
Do not add a second effect that reruns layout on selection or tab changes — this is explicitly called out as a regression risk.

**Zoom min/max (D-20, new)** — add `minZoom`/`maxZoom` to the `<CytoscapeComponent>` props alongside the existing `layout`/`stylesheet`/`style` props (lines 106-110), or set via `cy.minZoom()`/`cy.maxZoom()` inside the same guarded `cy={...}` callback block used for listener wiring — pick whichever keeps the "module-scope layout options function" (`layoutOptionsFor`, lines 25-29) as the single source for spacing/padding constants, since D-19 requires tuning these together.

## Shared Patterns

### Design-token-driven styling (all components)
**Source:** `frontend/src/index.css` lines 8-146
**Apply to:** every restyled component — colors/spacing/radii must reference the token layer via Tailwind utility classes (`bg-card`, `text-muted-foreground`, `border-border`, `rounded-lg`) or `var(--token-name)` in raw CSS/Cytoscape style objects — never new hardcoded hex values outside `index.css`, `graphStylesheet.ts`, or `relationshipStyles.ts`. D-14 explicitly wants the palette to stay reconcilable with the current `#0F172A`/`#192134`/`#7C3AED`/`#6366F1` system.

### Module-scope Cytoscape registration + ref-guarded live-instance wiring
**Source:** `frontend/src/components/graph/GraphCanvas.tsx` lines 9-23 (registration), lines 93-94 + 111-115 (ref guard)
**Apply to:** any new Cytoscape extension registration or new `cy.on(...)` listener — must be added inside the existing guarded block, never a new unguarded `useEffect` that re-registers listeners on every render.

### `useMemo`/effect keyed on `[graph]`
**Source:** `frontend/src/components/graph/GraphCanvas.tsx` line 86 (`elements`), lines 99-103 (`runLayout` effect)
**Apply to:** any new derived-from-`graph` computation (style lookups, per-episode node/edge counts for a legend, etc.) — must be memoized on `[graph]`, never recomputed inline per render, to avoid re-triggering `cose-bilkent` layout thrashing (Phase 2 Plan 04 regression).

### Centralized single-branch routing in `App.tsx`
**Source:** `frontend/src/App.tsx` lines 93-98
```typescript
{selectedElement?.kind === 'edge' &&
graphState.data.edges.find((edge) => edge.id === selectedElement.id)?.claim_id == null ? (
  <StructuralEdgeCard selected={selectedElement} nodes={graphState.data.nodes} />
) : (
  <DetailPanel selected={selectedElement} graph={graphState.data} />
)}
```
**Apply to:** do not duplicate this claim_id-based routing decision anywhere else (e.g. inside a new legend or hover-preview component) — if a new component needs to know "is this a structural or claim-backed edge," it should receive that as a prop/derived value from this same branch, not re-derive it independently.

### shadcn/Radix primitive usage (`Sheet`, `Select`, `Tabs`, `Button`, `Card`)
**Source:** `frontend/src/components/ui/*.tsx` (10 installed primitives); usage sites `DetailPanel.tsx` lines 1-9, `StructuralEdgeCard.tsx` lines 1-6, `EpisodeSelector.tsx`/`SeriesSelect.tsx` lines 1-7, `AppShell.tsx` lines 2-4
**Apply to:** all new UI surfaces (legend, zoom controls, restyled selectors) — reuse these 10 existing primitives; do not add a second component library or hand-roll a dialog/select/tabs implementation. `cn()` from `frontend/src/lib/utils.ts` is the class-merge helper used throughout `ui/*.tsx` (e.g. `card.tsx` line 3) — use it for any new component with a `className` prop and conditional classes.

### TypeScript/style conventions (all new/modified `.ts`/`.tsx`)
**Source:** observed uniformly across all files read (no semicolons, single quotes in relative-import files, double quotes in shadcn-generated `ui/*.tsx` files — both coexist, follow whichever convention the specific directory already uses), strict typing (no file read used `any`), named exports for components (`export function ComponentName(...)`, never default export except `App.tsx`'s `export default App` at line 132).
**Apply to:** all new files. Match the surrounding directory's existing quote/semicolon style rather than imposing one style everywhere (e.g. new files under `components/graph/` and `components/detail/` should follow the no-semicolon/single-quote style seen in `GraphCanvas.tsx`/`DetailPanel.tsx`; if a new file lives directly beside `ui/*.tsx` shadcn output, that subtree's double-quote/semicolon style is shadcn-tool-generated and should not be hand-edited to match — but no new files are planned inside `ui/`, so this is unlikely to matter).
