<objective>
Implement Stage 1 (Propose) of the safe graph-editing agent: a typed `ChangeSet` built only through an
explicit Pydantic discriminated union of operation types, server-side ontology/visibility/origin
validation before any persistence, and the canonical/candidate protection invariant that converts a
requested canonical edit into a user-origin override proposal instead of a rejection with nothing
offered.

Purpose: this is the propose half of RAG-11/RAG-12/RAG-13 — the point where "the LLM proposes tool
calls, never executes Cypher" becomes concrete and testable. No database mutation of a target resource
happens in this plan; that is Stage 2 (06-06).
Output: `backend/app/domain/change_set.py`'s operation discriminated union, `ChangeSetRepository`
(propose-only), and `POST /api/series/{series_id}/change-sets` (adapt name to convention) returning a
`draft`/`awaiting_confirmation` ChangeSet with zero graph-target mutation.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LLM-constructed ChangeSet payload -> propose endpoint | Model output is untrusted; every field is re-validated server-side regardless of what the model claims |
| Canonical/candidate resource -> mutation request | Must never be directly writable by the assistant under any operation type |

| T-06-01 | Tampering | domain/change_set.py, api/change_set.py | critical | mitigate | The LLM never executes Cypher; it can only populate a closed Pydantic discriminated union, itself rejecting raw-Cypher-shaped or arbitrary-label payloads (Task 1) |
| T-06-05 | Elevation of Privilege / Tampering | services/change_set.py | critical | mitigate | Server-side ontology/visibility/series/origin validation before any persistence; canonical/candidate always non-mutable (Task 2, Task 3) |
