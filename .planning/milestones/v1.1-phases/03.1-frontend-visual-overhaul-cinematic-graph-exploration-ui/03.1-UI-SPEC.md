## Spacing Scale

Declared values (must be multiples of 4) — **unchanged from Phase 2**, still governs UI chrome only:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge/chip internal padding, legend swatch-to-label gap |
| sm | 8px | Compact spacing, legend row gaps, GraphControls button gaps |
| md | 16px | Default element spacing, card padding, panel section gaps |
| lg | 24px | Section padding (detail panel body, modal body) |
| xl | 32px | Layout gaps (canvas ↔ side panel gutter, top bar height padding) |
| 2xl | 48px | Major section breaks (top bar height) |
| 3xl | 64px | Page-level spacing (unused unless a full-page empty state is needed) |

Exceptions (unchanged + one addition):
- Icon-only touch targets (Cytoscape zoom/fit/reset buttons, legend collapse toggle): 44×44px minimum hit area — overrides the 4px-multiple aesthetic scale for hit-area only, not visual padding. Visual icon size stays 16–20px; the 44px is achieved via button padding, not icon inflation.
- Node/edge canvas layout spacing is controlled by the `cose-bilkent` (or `cose` fallback) force-directed layout engine, not the 8-point scale. This phase changes the *engine's own tuning values* (not the UI-chrome scale) — see Graph Canvas Visual System below.
- **New:** `GraphLegend` and `GraphControls` are positioned as floating overlays on top of the canvas (bottom-left and bottom-right respectively) with a fixed `16px` (`md`) inset from the canvas edges, sized so neither ever covers more than the bottom ~15% of canvas height at the smallest supported viewport (D-30 "never cover graph content").

## Typography

| Role | Size | Weight | Line Height | Font |
|------|------|--------|-------------|------|
| Body | 14px | 400 (regular) | 1.5 | Inter Variable |
| Label | 12px | 600 (semibold) | 1.5 | Inter Variable — badges, node-type legend rows, metadata captions (episode locator, confidence level), Cytoscape canvas node/edge labels (unchanged 10px/9px canvas-specific sizes below) |
| Heading | 18px | 600 (semibold) | 1.2 | Space Grotesk Variable — panel section titles, modal title, legend header |
| Display | 24px | 600 (semibold) | 1.2 | Space Grotesk Variable — top bar series/episode title only |

Scale is **unchanged in size/weight from Phase 2** (14/12/18/24, 400/600) — only the font-family assignment changes per role, per D-13. Rationale for keeping the same numeric scale: `ui-ux-pro-max --domain typography "space grotesk inter"` returned the exact Space Grotesk (headings) + Inter (body) pairing as a validated real-world dark-tech pairing ("Web3/DeFi", "Tech Startup" entries) — confirming the *font choice* is sound without requiring a *size-scale* change; Phase 2's 14/12/18/24 tool-like density remains correct for this data-dense graph-inspection product.

Canvas-specific label sizes (Cytoscape `graphStylesheet.ts`, outside the chrome type scale, unchanged from Phase 2 unless noted):
- Node label: 10px, Inter Variable (was inherited system default — now explicit), single-line ellipsis truncation at `text-max-width: 80px` (unchanged), full text via native `title` tooltip on hover (unchanged Phase 2 mechanism).
- Edge label: 9px, Inter Variable, same truncation rule.
- **New:** Episode node tag label additionally shows the episode `code` (e.g. "S01E02") as the primary label text (already the case — `node.label` already carries this per `graphElements.ts`); no new data plumbing needed, just confirm the tag-shape sizing (below) keeps it legible at 10px.

No third font family (e.g. a monospace for timestamps/confidence numerics) is added this phase — `ui-ux-pro-max` surfaced JetBrains Mono as a common tri-stack companion, but `03.1-CONTEXT.md`'s Claude's-discretion note only permits *additional weights/subsets* of the two named Fontsource packages, not a third family. If tabular alignment of numeric evidence locators/timestamps is desired, use `font-variant-numeric: tabular-nums` on Inter rather than a new font.

## Graph Canvas Visual System

> This section is this phase's primary "Visuals" dimension deliverable — the graph is the hero
> of the application (D-specifics), so canvas tuning is as load-bearing as the color/typography

### Layout & zoom tuning (D-18, D-19, D-20 — tune `cose-bilkent`, do not replace it)

`layoutOptionsFor('cose-bilkent')` in `GraphCanvas.tsx` gains explicit tuning values (all additive to the existing `{ name: 'cose-bilkent', nodeDimensionsIncludeLabels: true, fit: true, padding: 24 }` object — the try/catch fallback-to-`cose` mechanism and the `[graph]`-keyed `useEffect`/`runLayout` re-run pattern are preserved exactly, D-21):

| Option | Current | New | Rationale |
|--------|---------|-----|-----------|
| `padding` | 24 | 48 | More breathing room around the fitted graph — directly targets the "tiny centered cluster in empty canvas" complaint |
| `nodeRepulsion` | (library default, ~4500) | 8000 | Spreads nodes further apart at the new larger 44px+ sizes so labels don't collide |
| `idealEdgeLength` | (library default) | 100 | Slightly longer edges to match increased node sizes/repulsion |
| `edgeElasticity` | (library default) | 0.45 | Slightly looser than default, complements the repulsion increase without producing a sparse/disconnected look |
| `nodeDimensionsIncludeLabels` | `true` | `true` (unchanged) | Already correctly accounts for label bounding boxes |
| `fit` | `true` | `true` (unchanged) | Already correct |

Cytoscape instance-level zoom constraints (new, D-20 — none exist today): `minZoom: 0.3`, `maxZoom: 2.5`, set as `cy` init options (or via the `cy` callback ref) alongside the existing `wiredCyRef` guard so they are only ever set once per real instance.

If, after this tuning, `RESEARCH.md` finds `cose-bilkent` still cannot resolve the empty-canvas complaint at typical S01E03 volume (20 nodes / ~10 edges), only then does D-18's "add `fCoSE`" escape hatch apply — with explicit justification recorded in `RESEARCH.md` before the planner locks it in. Default assumption for this UI-SPEC is that tuning succeeds.

### Selection, neighborhood, hover (D-26, D-27 — extend the class contract, evolve the color computation)

- Selected node: `.selected-dominant` gets the existing `#7C3AED` ring (unchanged 3px width) **plus** a restrained single-element glow using Cytoscape's native halo properties: `'overlay-color': '#7C3AED', 'overlay-opacity': 0.35, 'overlay-padding': 8` — **correction post-research (03.1-RESEARCH.md Pitfall 1): Cytoscape has no `shadow-*` style property and cannot apply CSS `box-shadow` to a canvas-rendered node; `overlay-*` is the real, confirmed-in-`@types/cytoscape` mechanism** — applied only to the one currently-selected node (D-35 perf constraint: never a per-element continuous shadow/overlay on the full node set) — plus the 1.15× size growth from the node-type table above. Hovered (not-yet-selected) nodes get a subtler variant: `'overlay-opacity': 0.15, 'overlay-padding': 6`.
- Faded (unrelated content): `opacity: 0.25` (nodes) / `0.15` (edges) — **unchanged values**, "dim rather than disappear" is already the correct design per D-26, only re-confirmed here.
- Connected-edge highlight on selection/hover (`edge-active`/`hovered` classes): **behavior changes from Phase 2.** Phase 2 forced `line-color: #6366F1` (indigo) on every hovered/active edge regardless of type — this is no longer correct now that edges carry real per-relationship-type colors (D-28 is new this phase). New rule: hovered/active edges **keep their own relationship-type color** (from the table above) and instead signal "active" via `width: 2.5 → 3.5` and guaranteed full `opacity: 1` (overriding any inherited `faded` class) plus arrow-scale `1.3×`. This is a required, explicit supersession of one Phase 2 stylesheet rule (the `edge.hovered, edge.edge-active` selector's `line-color`/`target-arrow-color` properties), not a silent drift — document it in code as such.
- **New (D-27):** hovering a **node** (not just an edge) must brighten that node's own connected edges — wire a `cy.on('mouseover'/'mouseout', 'node', ...)` pair that adds/removes the same `hovered` class on `node.connectedEdges()`, alongside the existing native-`title`-tooltip mouseover/mouseout handlers (both can coexist on the same event). Hover never opens `DetailPanel` — click/tap remains the only selection trigger (unchanged).

### Legend (D-30, new component)

- Single collapsible panel, bottom-left corner of the canvas, `16px` inset.
- Two grouped sections: "Node Types" (8 rows: shape glyph + color swatch + type name, from the node table above) and "Relationships" (9 rows: color swatch + group name, from the relationship table above — collapse the 3 zero-instance-today rows — `LOCATED_IN`, provenance group, revision group — into a visually de-emphasized "forward-compat" sub-group rather than omitting them, since they are ontology-real, just not in the current Dexter S01E01-03 seed).
- Default state on first load: **collapsed** (Claude's discretion, resolved) — maximizes canvas real estate for the "graph as hero" priority; a single `Legend` label + chevron toggle sits inset in the corner when collapsed, expanding upward.

### Performance (D-35)

- No new `cy.on(...)` listener is added without the same module-scope-registration + `wiredCyRef`-guarded re-wiring pattern already used for the existing tap/hover listeners.

- No new derived-data computation (style lookups, the new `claimStatus` resolution) skips the existing `useMemo`-on-`[graph]` pattern — extend the existing memoized `elements` computation rather than adding a second unmemoized pass.
- Grid/glow background is static CSS (`background-image`/`radial-gradient`), never recomputed per frame or per Cytoscape pan/zoom event.
