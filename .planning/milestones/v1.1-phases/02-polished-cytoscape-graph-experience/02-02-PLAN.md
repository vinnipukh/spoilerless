<objective>
Expand the tracer's minimal Cytoscape rendering (Plan 01: built-in `cose` layout, bare label-only stylesheet) into the polished visual language locked by 02-UI-SPEC.md: the `cose-bilkent` force-directed layout, full node-type shape and origin-border stylesheet (including the two node types - `Episode` and `Series` - that 02-UI-SPEC.md's table never assigned a shape to, per 02-RESEARCH.md Pitfall 2), selection-driven neighbor highlight/fade (D-05's "nothing is inert to clicks"), and explicit loading/error/empty overlay states.

This is horizontal expansion on top of the Plan 01 tracer - GraphCanvas's public `onSelect` contract and `graphElements.ts`'s mapping-function signature are unchanged; only their internals and the stylesheet/layout gain depth.

Purpose: satisfy UI-03's requirement that the canvas "must not look like default Cytoscape output" and that it visibly updates as episode boundaries change.
Output: A fully-styled, layout-tuned Cytoscape canvas with loading/error/empty states and a component test proving element counts track the backend boundary exactly.
</objective>

## Open Assumption (surfaced, not silently dropped)

02-UI-SPEC.md's UI Considerations table leaves long-text handling for canvas node labels **unresolved**: no truncation rule is locked for unusually long character/claim labels. This plan proceeds with a default assumption - single-line ellipsis truncation on the node label with the full text available via a hover-tooltip - rather than inventing a silent behavior. This is an explicit open assumption, not a covered/backstop must-have; if the Dexter S01E01-03 seed data surfaces a genuinely long label during UAT, revisit this default.
