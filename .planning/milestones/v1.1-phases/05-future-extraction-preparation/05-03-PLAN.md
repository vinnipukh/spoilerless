<threat_model>
- **Unauthorized promotion (ASVS V5):** Only the approve endpoint can change a candidate's status to 'canonical'. No other API path, Cypher query, or seed script can promote candidates. The `origin: 'candidate'` check in Cypher prevents accidental promotion of canonical or user claims.
- **Rejection bypass (ASVS V11):** Rejected claims must stay rejected. The reject endpoint sets `status: 'rejected'` and no other endpoint unsets it.
- **Immutable field mutation (ASVS V5):** Edit (PATCH) must reject attempts to change `id`, `series_id`, `origin`, or `visible_from_order`. Enforcement happens both in the API route (via `allowed_fields` allowlist) and in Cypher (those fields are never in the SET clause).
- **Revision integrity (ASVS V11):** Every approve, reject, and edit must create a Revision in the same Neo4j transaction as the mutation. If the revision creation fails, the entire transaction rolls back, preventing an unrevisioned status change.
- **Revision disclosure (ASVS V7):** Revision before/after snapshots include the full claim state. The visible_from_order of the revision is derived from the claim's visible_from_order, ensuring proper spoiler filtering.
- **Idempotency (ASVS V8):** Approve/reject are idempotent — approving an already-canonical claim is a no-op that still creates a revision (the before/after are identical). This is intentional for audit trail completeness.
</threat_model>

**New route: POST /api/series/{series_id}/candidates/{claim_id}/approve**

```python
import hashlib
import json

@router.post(
    "/{claim_id}/approve",
    response_model=dict,
    summary="Approve a candidate claim, promoting it to canonical status",
    responses={
        200: {"description": "Candidate approved and revision logged."},
        404: {"description": "Candidate not found.", "model": dict},
        409: {"description": "Claim is not a candidate.", "model": dict},
    },
)
async def approve_candidate(
    series_id: SeriesId,
    claim_id: ClaimId,
    repo: CandidateRepoDependency,
) -> dict:
    """Approve a candidate claim, changing status from 'candidate' to 'canonical'.
    
    Creates a Revision in the same transaction (D-15). Only operates on
    claims with origin: 'candidate' (D-17).
    """
    db = get_database()

    def _approve_with_revision(tx):
        # 1. Read current state
        read_query = """
        MATCH (claim:Claim {id: $claim_id, series_id: $series_id})
        RETURN claim.id AS id, claim.status AS status,
               claim.origin AS origin, claim.label AS label,
               claim.predicate AS predicate, claim.claim_type AS claim_type,
               claim.confidence_level AS confidence_level,
               claim.relationship_effect AS relationship_effect,
               claim.visible_from_order AS visible_from_order,
               claim.valid_from_order AS valid_from_order,
               claim.valid_until_order AS valid_until_order
        """
        current = list(tx.run(read_query, claim_id=claim_id, series_id=series_id))
        if not current:
            raise http_error(404, "candidate_not_found", f"Candidate claim not found: {claim_id}")

        row = current[0]
        if row["origin"] != "candidate":
            raise http_error(
                409, "cannot_approve_non_candidate",
                f"Claim '{claim_id}' has origin '{row['origin']}', not 'candidate'. Only candidates can be approved.",
            )

        if row["status"] == "canonical":
            # Already approved — idempotent. Still log revision for audit trail.
            pass

        before_snapshot = dict(row)
        after_snapshot = dict(before_snapshot)
        after_snapshot["status"] = "canonical"

        # 2. Update status
        update_query = """
        MATCH (claim:Claim {id: $claim_id, series_id: $series_id, origin: 'candidate'})
        SET claim.status = 'canonical'
        RETURN claim.id AS id, claim.status AS status
        """
        tx.run(update_query, claim_id=claim_id, series_id=series_id)

        # 3. Log revision (D-15, D-35)
        revision_id = f"revision:{hashlib.sha256(f'approve:{claim_id}:{datetime.now(timezone.utc).isoformat()}'.encode()).hexdigest()[:12]}"
        RevisionRepository._log_revision(
            tx=tx,
            revision_id=revision_id,
            series_id=series_id,
            resource_type="Claim",
            resource_id=claim_id,
            action=RevisionAction.UPDATED,
            before=before_snapshot,
            after=after_snapshot,
            visible_from_order=before_snapshot.get("visible_from_order", 1),
        )

        return {
            "id": claim_id,
            "status": "canonical",
            "origin": "candidate",
            "revision_id": revision_id,
        }

    try:
        return db.execute_write(_approve_with_revision)
    except HTTPException:
        raise
    except Exception as exc:
        raise http_error(422, "invalid_extraction_payload", f"Approve error: {exc}")
```

**New route: PATCH /api/series/{series_id}/candidates/{claim_id}**

```python
ALLOWED_EDIT_FIELDS = {
    "label", "predicate", "claim_type", "confidence_level",
    "relationship_effect", "valid_from_order", "valid_until_order",
    "evidence_text", "evidence_locator", "source_type", "source_locator",
}


class CandidateEditRequest(BaseModel):
    """Schema for editing a candidate claim's mutable fields (D-16)."""
    updates: dict[str, Any]

    model_config = ConfigDict(extra="forbid")

    @model_validator(mode="after")
    def validate_updates(self) -> CandidateEditRequest:
        invalid = set(self.updates.keys()) - ALLOWED_EDIT_FIELDS
        if invalid:
            raise ValueError(
                f"Fields not editable: {', '.join(sorted(invalid))}. "
                f"Allowed: {', '.join(sorted(ALLOWED_EDIT_FIELDS))}"
            )
        # Re-validate ontology-constrained fields
        for key, value in self.updates.items():
            if key == "claim_type":
                from backend.app.graph.ontology import Ontology
                Ontology.require_claim_type(value)
        return self


@router.patch(
    "/{claim_id}",
    response_model=dict,
    summary="Edit a candidate claim's mutable fields",
    responses={
        200: {"description": "Candidate updated and revision logged."},
        404: {"description": "Candidate not found.", "model": dict},
        409: {"description": "Claim is not a candidate.", "model": dict},
        422: {"description": "Invalid edit payload.", "model": dict},
    },
)
async def edit_candidate(
    series_id: SeriesId,
    claim_id: ClaimId,
    edit_request: CandidateEditRequest,
    repo: CandidateRepoDependency,
) -> dict:
    """Edit a candidate claim's mutable fields.
    
    Allowed fields: label, predicate, claim_type, confidence_level,
    relationship_effect, valid_from_order, valid_until_order,
    evidence_text, evidence_locator, source_type, source_locator.
    
    Immutable fields (id, series_id, origin, visible_from_order) are rejected.
    Creates a Revision with before/after snapshots (D-15, D-16).
    """
    db = get_database()

    def _edit_with_revision(tx):
        read_query = """
        MATCH (claim:Claim {id: $claim_id, series_id: $series_id})
        RETURN claim.id AS id, claim.origin AS origin,
               claim.label AS label, claim.predicate AS predicate,
               claim.claim_type AS claim_type, claim.status AS status,
               claim.confidence_level AS confidence_level,
               claim.relationship_effect AS relationship_effect,
               claim.visible_from_order AS visible_from_order,
               claim.valid_from_order AS valid_from_order,
               claim.valid_until_order AS valid_until_order,
               claim.schema_version AS schema_version
        """
        current = list(tx.run(read_query, claim_id=claim_id, series_id=series_id))
        if not current:
            raise http_error(404, "candidate_not_found", f"Candidate claim not found: {claim_id}")

        row = current[0]
        if row["origin"] != "candidate":
            raise http_error(
                409, "cannot_approve_non_candidate",
                f"Claim '{claim_id}' has origin '{row['origin']}', not 'candidate'. Only candidates can be edited.",
            )

        before_snapshot = dict(row)
        after_snapshot = dict(before_snapshot)
        after_snapshot.update(edit_request.updates)

        # Build dynamic SET
        set_clauses = [f"claim.{k} = ${k}" for k in edit_request.updates]
        set_expr = ", ".join(set_clauses)

        update_query = f"""
        MATCH (claim:Claim {{id: $claim_id, series_id: $series_id, origin: 'candidate'}})
        SET {set_expr}
        RETURN claim.id AS id, claim.status AS status
        """
        params = {"claim_id": claim_id, "series_id": series_id, **edit_request.updates}
        tx.run(update_query, **params)

        revision_id = f"revision:{hashlib.sha256(f'edit:{claim_id}:{datetime.now(timezone.utc).isoformat()}'.encode()).hexdigest()[:12]}"
        RevisionRepository._log_revision(
            tx=tx,
            revision_id=revision_id,
            series_id=series_id,
            resource_type="Claim",
            resource_id=claim_id,
            action=RevisionAction.UPDATED,
            before=before_snapshot,
            after=after_snapshot,
            visible_from_order=before_snapshot.get("visible_from_order", 1),
        )

        return {
            "id": claim_id,
            "status": after_snapshot.get("status", before_snapshot.get("status")),
            "origin": "candidate",
            "revision_id": revision_id,
            "updated_fields": list(edit_request.updates.keys()),
        }

    try:
        return db.execute_write(_edit_with_revision)
    except HTTPException:
        raise
    except ValueError as exc:
        raise http_error(422, "invalid_extraction_payload", str(exc))
    except Exception as exc:
        raise http_error(422, "invalid_extraction_payload", f"Edit error: {exc}")
```

**Key design decisions:**
- Each approve/reject/edit operation is a read-then-write within a single `execute_write` callback. This ensures the before-snapshot captures the exact pre-mutation state (D-15).
- Revision logging uses `RevisionRepository._log_revision` directly (the private method name may vary — use `RevisionRepository.log_revision` if that's the public API). This follows the same pattern used in `backend/app/repository/user_content.py` (D-35).
- The `CandidateEditRequest` model uses a `model_validator` to enforce the allowlist of editable fields and re-validate ontology-constrained fields like `claim_type` (D-16).
- Error codes per D-29: `candidate_not_found` (404), `cannot_approve_non_candidate` (409), `cannot_reject_non_candidate` (409), `invalid_extraction_payload` (422).
- Read queries before mutation check `origin: 'candidate'` to prevent accidental promotion of canonical or user claims (D-17).
- The list and get endpoints were already created in Plan 05-02 — they serve as the candidate listing for review workflow (D-18, D-19).
