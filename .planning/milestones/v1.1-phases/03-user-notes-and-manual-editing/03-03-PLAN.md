<objective>
Integrate API-owned custom content into the one existing spoiler-safe graph, complete OpenAPI corrections and setup regressions, and publish the backend-to-frontend handoff. This plan is the exclusive owner of `backend/app/api/graph.py` and `backend/app/spoiler/filter.py`; it closes backend acceptance for NOTE-01, NOTE-02, and NOTE-03 while explicitly preserving D-01 through D-28 and leaving visual/UI acceptance pending in `frontend-work`.
</objective>

<threat_model>
- **Spoofing / content-classification bypass (ASVS V4):** a malformed Claim might masquerade as a user edge to bypass evidence. Mitigation: user projection requires all of `origin='user'`, `claim_type='user_authored'`, `user-rel:` namespace, safe predicate, same series, and visible endpoints; regression injects evidence-free canonical/candidate claims and proves they remain absent.
- **Tampering / query broadening (ASVS V5):** broad OPTIONAL MATCH or generic relationship traversal could weaken provenance or expose structural data. Mitigation: preserve evidence-backed queries unchanged in principle; add one separate parameterized `VISIBLE_USER_RELATIONSHIPS_QUERY`; static allowlist parameter; review tests inspect canonical evidence paths and exact projections.
- **Information disclosure (ASVS V7):** missing visibility, hidden endpoints, counts, labels, errors, or OpenAPI ambiguity can leak future facts. Mitigation: required positive integer boundary plus persisted boundary check, positive visibility predicates on edge and both endpoints before projection, absent/malformed records excluded, serialized sentinel/count and hidden-vs-missing tests.
- **Denial of service / integrity (ASVS V5/V12):** dangling edges can break response construction and setup can overwrite user work. Mitigation: Cypher closure plus retained Pydantic closure validator; setup rerun with existing/deleted user fixtures; deterministic ordering and bounded graph response; canonical/user snapshots before and after.
- Any HIGH finding blocks handoff; the full suite and live setup must pass before documentation is accepted.
</threat_model>
