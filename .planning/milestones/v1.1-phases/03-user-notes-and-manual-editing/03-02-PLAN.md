<threat_model>
- **Spoofing / unauthorized resource ownership (ASVS V4):** callers can guess canonical/candidate IDs or user namespaces. Mitigation: every PATCH/DELETE transaction matches expected label/representation, path `series_id`, `origin='user'`, and `user-note:`/`user-node:`/`user-rel:` namespace; canonical/candidate before/after snapshots and generic 409/404 tests block mutation.
- **Tampering / injection / TOCTOU (ASVS V5):** unchecked labels/predicates or separate validation and mutation can alter arbitrary graph data. Mitigation: static server-owned query maps selected only after enum+ontology checks, parameterized values, explicit SET clauses, and one `session.execute_write` callback containing series/episode/target/ownership checks plus mutation.
- **Information disclosure (ASVS V7):** hidden resources can leak through direct lookup, filter counts, ownership classification, cross-series errors, or Neo4j exceptions. Mitigation: persisted boundary first; visibility/series/target predicates in Cypher before projection; identical hidden/missing 404; arrays without total metadata; sanitized error codes/messages and 503 tests.
- **Denial of service / integrity (ASVS V5/V12):** retry callbacks can duplicate writes and custom-node deletion can cascade. Mitigation: generate UUID/timestamps once before retry; uniqueness constraints; callback has no external side effects; reject in-use node deletion with 409; hard-delete only exact API-owned resources after dependency checks.
- HIGH findings block completion; targeted live tests must prove each mitigation before Plan 03-03.
</threat_model>
