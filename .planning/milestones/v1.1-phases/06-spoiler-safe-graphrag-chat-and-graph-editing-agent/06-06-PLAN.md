<objective>
Implement Stage 2 (Confirm and Apply) of the safe graph-editing agent: fresh re-validation at confirm
time, transactional apply of every operation plus a single Revision log entry inside one Neo4j write
transaction, idempotency-key replay protection, and staleness rejection when the user's progress has
dropped below the ChangeSet's snapshot boundary since it was proposed.

Purpose: this is where RAG-12's "validate all operations before applying any... roll back the entire
ChangeSet on failure... prevent replay with an idempotency key" and RAG-14's "re-read current user,
progress, resource origin, resource version" become real, alongside RAG-15's audit requirement. This is
the single highest-consequence write path in the whole phase — it is the only place an LLM-originated
proposal actually touches the graph.
Output: `POST /api/series/{series_id}/change-sets/{change_set_id}/confirm` and
`POST .../reject`, transactional apply logging a Revision, idempotency-key-guarded.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Confirm request -> apply transaction | The single highest-consequence write path in the phase — must re-validate everything fresh, never trust the propose-time snapshot |
| Replayed/duplicated confirm request -> apply transaction | Client retries, network duplication, or malicious replay must not double-apply |
