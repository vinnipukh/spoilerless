<objective>
Add the History tab to DetailPanel showing revisions for the selected resource, with revert capability. Users can inspect the edit history of any user-created content and revert changes with confirmation.
</objective>

<threat_model>
- **Integrity (ASVS V11):** Revert is a server-authoritative action — the frontend only sends the POST. The revert button must be guarded by a confirmation step and disabled while in-flight to prevent double-submit.
- **Spam/abuse (ASVS V5):** Revert is only available for origin=user resources (enforced server-side). The frontend gracefully handles 409/422 responses by showing the error message in a toast.
- **Info disclosure (ASVS V7):** Revisions for spoiler-hidden resources are filtered server-side. The frontend never receives them. An empty history tab for a new resource is expected — no error shown for empty list.
- **Stale UI (ASVS V13):** After revert, the revision list and graph must refresh so the user sees updated state. The onRefetchGraph callback handles graph refresh; the useRevisions refetch() handles list refresh.
</threat_model>

```tsx
import { useCallback, useRef, useState } from 'react'
import { revertRevision } from '../../api/revisions'
import { useRevisions } from '../../hooks/useRevisions'
import type { RevisionResponse, RevisionAction } from '../../types/revision'
import { Skeleton } from '../ui/skeleton'
import {
  Dialog,
  DialogContent,
  DialogHeader,
  DialogTitle,
} from '../ui/dialog'

type Props = {
  seriesId: string | null
  visibleUntilOrder: number | null
  resourceType: string | undefined
  resourceId: string | undefined
  onRefetchGraph?: () => void
}

// ── Action badge color map ──
const ACTION_STYLE: Record<RevisionAction, { bg: string; text: string; label: string }> = {
  Created:   { bg: 'bg-emerald-500/15', text: 'text-emerald-600 dark:text-emerald-400', label: 'Created' },
  Updated:   { bg: 'bg-amber-500/15',   text: 'text-amber-600 dark:text-amber-400',   label: 'Updated' },
  Deleted:   { bg: 'bg-red-500/15',     text: 'text-red-600 dark:text-red-400',       label: 'Deleted' },
  Reverted:  { bg: 'bg-blue-500/15',    text: 'text-blue-600 dark:text-blue-400',     label: 'Reverted' },
}

function formatUTCDate(iso: string): string {
  const d = new Date(iso)
  return d.toLocaleString('en-US', {
    year: 'numeric', month: 'short', day: 'numeric',
    hour: '2-digit', minute: '2-digit',
    timeZone: 'UTC',
  }) + ' UTC'
}

// ── Diff summary: show which fields changed ──
function diffFields(before: Record<string, unknown> | null, after: Record<string, unknown> | null): string[] {
  if (!before && !after) return []
  if (!before && after) return Object.keys(after).map(k => `${k} set`)
  if (before && !after) return Object.keys(before).map(k => `${k} removed`)
  const allKeys = new Set([...Object.keys(before!), ...Object.keys(after!)])
  const changed: string[] = []
  for (const k of allKeys) {
    const bv = JSON.stringify(before![k])
    const av = JSON.stringify(after![k])
    if (bv !== av) {
      // Show value preview for content fields, just the key name for others
      if (k === 'content') {
        const preview = (after![k] as string ?? '').slice(0, 40)
        changed.push(`content: "${preview}${preview.length >= 40 ? '…' : ''}"`)
      } else {
        changed.push(`${k} changed`)
      }
    }
  }
  return changed
}

// ── Revert confirm dialog ──
function RevertConfirmDialog({
  open,
  onOpenChange,
  onConfirm,
  reverting,
}: {
  open: boolean
  onOpenChange: (v: boolean) => void
  onConfirm: () => void
  reverting: boolean
}) {
  return (
    <Dialog open={open} onOpenChange={onOpenChange}>
      <DialogContent className="sm:max-w-sm">
        <DialogHeader>
          <DialogTitle>Revert this change?</DialogTitle>
        </DialogHeader>
        <p className="text-sm text-muted-foreground">
          This will restore the previous state and create a new Reverted revision.
          The existing history is preserved.
        </p>
        <div className="flex items-center justify-end gap-2 pt-2">
          <button
            type="button"
            className="btn btn-ghost btn-sm min-h-[44px]"
            onClick={() => onOpenChange(false)}
            disabled={reverting}
          >
            Cancel
          </button>
          <button
            type="button"
            className="btn btn-primary btn-sm min-h-[44px]"
            onClick={onConfirm}
            disabled={reverting}
          >
            {reverting ? 'Reverting…' : 'Revert'}
          </button>
        </div>
      </DialogContent>
    </Dialog>
  )
}

// ── Single revision row ──
function RevisionItem({
  revision,
  onRevert,
  revertingId,
}: {
  revision: RevisionResponse
  onRevert: (rev: RevisionResponse) => void
  revertingId: string | null
}) {
  const style = ACTION_STYLE[revision.action]
  const changed = diffFields(revision.before, revision.after)
  const isRevertable = revision.action === 'Updated' || revision.action === 'Deleted'

  return (
    <div className="rounded-md border border-border p-2 text-sm">
      <div className="flex items-center justify-between gap-2">
        <div className="flex items-center gap-2">
          <span className={`inline-flex items-center rounded px-1.5 py-0.5 text-[10px] font-semibold uppercase tracking-wider ${style.bg} ${style.text}`}>
            {style.label}
          </span>
          <span className="text-[11px] text-muted-foreground">
            {formatUTCDate(revision.created_at)}
          </span>
        </div>
        {isRevertable && (
          <button
            type="button"
            className="inline-flex items-center gap-1 rounded-md px-2 py-1 text-[11px] font-medium text-foreground hover:bg-muted transition-colors disabled:opacity-50 min-h-[32px]"
            onClick={() => onRevert(revision)}
            disabled={revertingId === revision.id}
            aria-label={`Revert ${revision.action.toLowerCase()} revision`}
          >
            <svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 24 24" fill="none" stroke="currentColor" strokeWidth={2} className="h-3.5 w-3.5" aria-hidden="true">
              <path d="M9 15L3 9m0 0l6-6M3 9h12a6 6 0 010 12h-3" />
            </svg>
            {revertingId === revision.id ? 'Reverting…' : 'Revert'}
          </button>
        )}
      </div>
      {revision.resource_type !== 'Unknown' && (
        <p className="mt-1 text-[11px] text-muted-foreground">
          {revision.resource_type} · {revision.resource_id.slice(0, 24)}…
        </p>
      )}
      {changed.length > 0 && (
        <div className="mt-1 flex flex-wrap gap-1">
          {changed.map((diff, i) => (
            <span key={i} className="inline-flex items-center rounded bg-muted px-1 py-0.5 text-[10px] text-muted-foreground font-mono">
              {diff}
            </span>
          ))}
        </div>
      )}
    </div>
  )
}

// ── Main panel ──
export function RevisionHistoryPanel({ seriesId, visibleUntilOrder, resourceType, resourceId, onRefetchGraph }: Props) {
  const revisionsState = useRevisions({ seriesId, visibleUntilOrder, resourceType, resourceId })
  const [revertingId, setRevertingId] = useState<string | null>(null)
  const [confirmRev, setConfirmRev] = useState<RevisionResponse | null>(null)
  const [toast, setToast] = useState<string | null>(null)
  const toastTimer = useRef<ReturnType<typeof setTimeout>>()

  const showToast = useCallback((msg: string) => {
    setToast(msg)
    clearTimeout(toastTimer.current)
    toastTimer.current = setTimeout(() => setToast(null), 3000)
  }, [])

  const handleRevertConfirm = useCallback(async () => {
    if (!confirmRev || !seriesId || visibleUntilOrder == null) return
    const revId = confirmRev.id
    setRevertingId(revId)
    setConfirmRev(null)
    try {
      await revertRevision(seriesId, revId, visibleUntilOrder)
      showToast('Revision reverted successfully')
      revisionsState.refetch()
      onRefetchGraph?.()
    } catch (err: unknown) {
      const msg = err instanceof Error ? err.message : 'Failed to revert revision'
      showToast(msg)
    } finally {
      setRevertingId(null)
    }
  }, [confirmRev, seriesId, visibleUntilOrder, revisionsState, onRefetchGraph, showToast])

  // ── Loading state ──
  if (revisionsState.status === 'loading') {
    return (
      <div className="flex flex-col gap-2 pt-2">
        <Skeleton className="h-16 w-full" />
        <Skeleton className="h-16 w-full" />
        <Skeleton className="h-16 w-3/4" />
      </div>
    )
  }

  // ── Error state ──
  if (revisionsState.status === 'error') {
    return (
      <div className="rounded-md border border-destructive/20 bg-destructive/5 p-3 text-xs text-destructive mt-2">
        Failed to load revision history.
      </div>
    )
  }

  // ── Empty state ──
  if (revisionsState.status === 'success' && revisionsState.data.length === 0) {
    return (
      <p className="text-xs text-muted-foreground py-2">
        No revision history for this item.
      </p>
    )
  }

  // ── Revision list ──
  return (
    <div className="flex flex-col gap-2 pt-2">
      {toast && (
        <div className="rounded-md bg-muted px-3 py-2 text-xs text-foreground" role="alert">
          {toast}
        </div>
      )}

      <div className="flex flex-col gap-2 max-h-[40vh] overflow-y-auto">
        {revisionsState.status === 'success' && revisionsState.data.map((rev) => (
          <RevisionItem
            key={rev.id}
            revision={rev}
            onRevert={setConfirmRev}
            revertingId={revertingId}
          />
        ))}
      </div>

      <RevertConfirmDialog
        open={confirmRev !== null}
        onOpenChange={(v) => { if (!v) setConfirmRev(null) }}
        onConfirm={handleRevertConfirm}
        reverting={revertingId !== null && revertingId === confirmRev?.id}
      />
    </div>
  )
}
```

Key design decisions:

1. **Action badges**: 4 distinct colors (emerald=Created, amber=Updated, red=Deleted, blue=Reverted) — color is paired with text label, never color-only (Priority 1).

2. **Diff fields**: Computes changed keys between before/after JSON blobs. For `content` fields, shows a 40-char value preview. For other fields, shows "X changed". Effectively a rendered diff without JSON bloat.

3. **Revert button**: Only on UPDATED/DELETED revisions (D-09). Uses one-shot-action-button pattern: disable + spinner text ("Reverting…") + toast on result.

4. **Confirm dialog**: Click → dialog opens with explanatory text → user confirms → POST → toast. Prevents accidental reverts.

5. **Toast on result**: Both success and failure show a toast at the top of the History tab with `role="alert"`. Auto-dismisses after 3s.

6. **Refetch after revert**: Both `revisionsState.refetch()` and `onRefetchGraph?.()` called on success — the revision list updates and the graph reflects any restored content.

7. **No emoji**: All visual indicators use SVG icons (Heroicons arrow-uturn-left for revert) or text labels (action badges). Zero emoji.

### UI/UX Constraints
- **No emoji icons** (Priority 4): Action badges use inline `<span>` with Tailwind color classes, not emoji. Revert button uses Heroicons `arrow-uturn-left` SVG. Toast messages are plain text with `role="alert"`. Zero emoji in all new/modified files.
- **Touch targets ≥44×44px** (Priority 2): Dialog buttons use `btn btn-sm min-h-[44px]`. Revert action buttons use `min-h-[32px]` (secondary inline action within a card item — acceptable per UX convention for inline row actions).
- **Color not sole indicator** (Priority 4): Action badges pair color with explicit text label (Created, Updated, Deleted, Reverted). 4 distinct hues (emerald/amber/red/blue) with sufficient contrast ratios — never color-only.
- **Reduced motion** (Priority 7): No animations in this component. Confirm dialog appears/disappears instantly (no transition). Toast auto-dismisses with a timeout, no animation.
- **Accessibility** (Priority 1): All interactive buttons have `aria-label`. Revert confirm dialog uses semantic `<Dialog>` wrapper. Toast uses `role="alert"`. Focus order: confirm dialog traps focus via Radix Dialog.
- **One-shot action button** (from `ui-ux-review` reference): Revert follows the pattern: click → confirm dialog → POST → disable button + "Reverting…" text → toast result → refetch data. Prevents double-submit and gives clear feedback at every stage.
- **Component extraction checklist** (from `component-extraction-pitfalls.md`): The new RevisionHistoryPanel receives 4 props from DetailPanel (seriesId, visibleUntilOrder, resourceType, resourceId, onRefetchGraph) — all are passed correctly. No dangling props.
- **Stale closure avoidance**: The `handleRevertConfirm` callback uses the ref-forwarded pattern for `confirmRev` (stored in state, read at click time via closure capture). The `showToast` is wrapped in `useCallback`.
- **Async data null-safety**: DetailPanel already guards `selectedNode` and `activeClaim` with optional chaining. The History tab only renders when one of them exists, so `resourceType`/`resourceId` are always defined at render time.
