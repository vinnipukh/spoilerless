### UI/UX Constraints

- **Color not sole indicator** (Priority 1): watched/unlocked vs currently-viewed vs locked/future must each carry a text or icon/affordance marker (e.g. locked = "Locked" text or lock Heroicon + muted label, currently-viewed = ring + "Now viewing" text). Verify the states are readable in grayscale. D-22 explicitly forbids color-only state communication.
- **No emoji icons** (Priority 4): any state icon uses Heroicons SVG (lock → Heroicons lock icon, check → Heroicons check icon), never emoji characters.
- **Touch targets ≥44×44px** (Priority 2): episode pill/option interactive targets keep min-h-[44px] min-w-[44px] or the existing h-11 token (h-11 = 44px); ≥8px gap between adjacent targets.
- **Accessibility** (Priority 1): generic titles must have accessible labels including the real episode code (e.g. aria-label "S01E05, Episode 5, locked"); ConfirmAdvanceModal must move focus to the dialog on open and return focus on close; keyboard tab order matches visual order; locked state never communicated by color alone.
- **Reduced motion** (Priority 7): no new animations; state changes are appear/disappear only.
- **No layout shift** (Priority 1, D-22): generic labels and real titles differ in width — use a stable min-width on the selector (e.g. min-w-[9rem] or a fixed-width pill) so switching labels does not reflow the header; do not clutter the header (D-22).
- **Stale closure avoidance**: any event handler reading viewAsOfOrder/watchedThroughOrder inside a useEffect must use the ref-forwarded callback pattern (const ref = useRef(cb); ref.current = cb).
- **Async data null-safety**: in App.tsx and EpisodeSelector render paths, all accesses to the episodes array and progress object use optional chaining (data?.display_title) — the async gap between selection and fetch can leave data undefined.
- **React 19 test workaround**: new hook/component tests use createRoot + flushSync (setup.ts act polyfill), not @testing-library/react render alone; test files with JSX stay .tsx.
