<objective>
Fix UAT gap G-06-4: after a user clicks Stop while an answer is streaming, the Stop button and the
Thinking/Streaming indicator never clear — both stay stuck forever, even though the underlying fetch has
genuinely been aborted and the backend generation has stopped. Root cause (fully diagnosed in
`.planning/debug/stop-button-thinking-indicator-stuck.md`): `useChatMessages.ts`'s `stop()` only calls
`abortControllerRef.current?.abort()` and never itself updates `status`; the sole place that handles the
resulting rejected `streamMessage()` promise — `sendChatMessage`'s `.catch` — deliberately no-ops when
`controller.signal.aborted` is true (to avoid showing an error banner for a user-initiated stop), which
leaves `status` frozen at `{status: 'streaming', ...}` indefinitely. `ChatPanel.tsx`'s Stop-button
visibility and `MessageList.tsx`'s Thinking/Streaming bubble are both derived solely from that same
`status` field, so both stay stuck.

Purpose: closes gap G-06-4 (severity major) from `06-UAT.md` Test 4 ("Stop generating button") — a chat
UI whose Stop button and loading indicator never clear is broken by definition and blocks Phase 6 UAT
sign-off.
Output: `useChatMessages.ts`'s aborted-catch branch transitions `status` to a terminal, non-streaming
value; the existing `stop()` regression test is extended to assert this.
</objective>
