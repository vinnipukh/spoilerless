<objective>
Complete RAG-15's revert requirement for ChangeSet-originated changes: reuse the existing Phase 4
revert pattern (`backend/app/api/revisions.py::revert_revision`) to let a user safely undo a
user-origin change a ChangeSet applied, without editing history and without silently overwriting an
unrelated later change.

Purpose: RAG-15 explicitly says "a minimal revert implementation is acceptable... but applied changes
must still be auditable" — this plan delivers that minimal, safe revert on top of 06-06's transactional
apply, reusing Phase 4's proven read-branch-apply-log shape rather than inventing a second revert
mechanism.
Output: `POST /api/series/{series_id}/change-sets/{change_set_id}/revert` (or equivalent route adapted
to the existing `/api/revisions/{id}/revert` convention if simpler to route through there — planner
discretion resolved in favor of a dedicated ChangeSet-scoped route for clearer ownership checks).
</objective>
