# Phase 6 — UI Design Contract

> Visual and interaction contract for the spoiler-safe GraphRAG chat and graph-editing agent
> frontend (RAG-16, RAG-17). Generated by gsd-ui-researcher, verified by gsd-ui-checker. This is an
> **integration** into the existing premium dark Cytoscape workspace, not a redesign — it extends
> `02-UI-SPEC.md` and `03.1-UI-SPEC.md` (both still authoritative for everything not explicitly
> overridden below) with the chat surface, citation UI, ChangeSet preview UI, and graph-focus sync.
> No token in `03.1-UI-SPEC.md`'s Design System/Spacing/Typography/Color sections is replaced here
> — this phase only **adds** chat-specific components and a small number of additive tokens,
> exactly as `03.1-UI-SPEC.md` added `--elevated` on top of the Phase 2 palette rather than
> replacing it.

## Spacing Scale

Declared values (must be multiples of 4) — **unchanged from Phase 2/03.1**, still governs UI chrome only:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge/chip internal padding, citation chip icon-to-label gap |
| sm | 8px | Compact spacing, message bubble vertical padding, citation chip padding, gap between consecutive messages from the same sender |
| md | 16px | Default element spacing, message bubble horizontal padding, ChangeSet card section gaps, gap between message groups from different senders |
| lg | 24px | Section padding (ChangeSet card body, chat empty-state padding) |
| xl | 32px | Layout gaps (unused directly by chat; inherited) |
| 2xl | 48px | Major section breaks (unused directly by chat; inherited) |
| 3xl | 64px | Page-level spacing (unused unless a full-height chat empty state needs vertical centering) |

Exceptions (additive to the existing Phase 03.1 exception list):
- Icon-only touch targets (chat launcher when icon-only on narrow screens, send button, stop button, citation "Show in graph" icon, retry icon): 44×44px minimum hit area, same rule as existing GraphControls buttons — visual icon size stays 16–20px, the 44px is achieved via padding.
- Message bubble max-width: 85% of the chat column width (not a spacing token — a layout constraint preventing a single message from spanning the full panel width, which reads poorly for long assistant answers).
- `GraphFocusIndicator` pill uses the same `16px` (`md`) fixed inset as `GraphLegend`/`GraphControls`, positioned `top-4 left-4` — the one remaining unclaimed corner of the canvas overlay grid (bottom-left: `GraphLegend` + Create Custom Node FAB; bottom-right: `GraphControls`; top-left: new `GraphFocusIndicator`; top-right: intentionally left clear, canvas breathing room).

| Role | Value | Usage |
|------|-------|------|
| Success | `#34D399` (emerald-400 — the identical hex already used as the "green" edge-color family for `TRUSTS`/`HELPS` in `relationshipStyles.ts`; reused, not a new color introduced into the palette) | ChangeSet "Applied" status badge/icon only. No other use. |

Rather than inventing an unrelated new hue, this reuses a hex already present and validated in the codebase's own semantic system, applied to exactly one new context (applied-ChangeSet confirmation), following the same "reuse before inventing" discipline `03.1-UI-SPEC.md` used for `--elevated`.

### Citation chip accents (reuse DetailPanel accents — do not invent new ones)

| Citation type | Accent | Rationale |
|----------------|--------|-----------|
| Claim citation | `#D946EF` (magenta — `CLAIM_ACCENT_COLOR` in `DetailPanel.tsx`) | Same visual meaning as the Claims tab card accent — a citation IS a pointer to that same claim record |
| Evidence citation | `#FB923C` (orange — `EVIDENCE_ACCENT_COLOR` in `DetailPanel.tsx`) | Same reuse logic — a citation to evidence should look like the Evidence tab card it points to |

### Accent (`#7C3AED`) reserved-for list — extended, not diluted

Accent is still never used for idle fills, default badges, or ChangeSet status (those use `--warning`/`--destructive`/`--success` as defined above).

## Copywriting Contract

UI chrome copy (buttons, labels, empty/error states, badges) is **English**, matching the existing shipped UI convention (`"Select a node to see details."`, `"No claims recorded for this node yet"`, etc.). This is distinct from **assistant message content**, which follows the user's question language per RAG-06/06-CONTEXT.md's "Localization" section (a backend/system-prompt concern, not a UI-chrome concern — this table does not dictate assistant prose, only the chrome around it).

| Element | Copy |
|---------|------|
| Primary CTA (chat launcher, top bar) | "Chat" (icon `MessageCircle` + label ≥768px; icon-only with `aria-label="Open chat"` / `aria-label="Close chat"` toggling by state on <768px) |
| Chat mode toggle (inside panel) | "Inspector" / "Chat" — two-segment control, same visual pattern as `EpisodeSelector`'s pill control |
| New conversation action | "New conversation" (icon `Plus`, `aria-label="Start new conversation"`) |
| Session picker placeholder (no session selected yet) | "Select a conversation" |
| Session picker empty state | Heading: "No conversations yet" · Body: "Ask a question below to start your first conversation." |
| Delete session (destructive confirmation, Dialog pattern matching `ConfirmAdvanceModal`) | Title: "Delete this conversation?" · Body: "This removes it from your conversation list. This can't be undone." · Cancel: "Cancel" · Confirm: "Delete" (destructive-styled) |
| Chat empty state (fresh session, no messages) | Heading: "Ask about {series title}" · Body: "Ask about characters, relationships, or events you've watched so far." · 3 suggestion chips (series-agnostic, no hardcoded entity names): "Who have I met so far?", "Summarize the story up to {current episode code}.", "Are there any tense relationships?" |
| Message input placeholder | "Ask about {episode code} and earlier…" (dynamic — reflects the user's current watched boundary, satisfying RAG-16's "clear current series and watched episode" requirement at the point of typing, not just in a badge) |
| Send button | Icon `Send`, `aria-label="Send message"` |
| Stop/cancel generation | "Stop generating" (icon `Square` + label; icon-only with same `aria-label` on narrow screens) |
| Retry on recoverable failure | "Retry" (icon `RotateCw`) — same verb as the existing `GraphErrorState`'s "Retry" button, deliberate consistency |
| Failed-message inline error | "Couldn't get a response. Retry?" (mirrors `GraphErrorState`'s "Couldn't load the graph..." tone exactly) |
| Series + watched-episode badge | "{series title} · up to {episode code}" e.g. "Dexter · up to S01E02" |
| Citation chip label | "{source_type} · {episode_code}" e.g. "Evidence · S01E01" |
| Citation "show in graph" action | Icon `Eye`, `aria-label="Show in graph"` |
| Citation with nothing to highlight (edge case) | No button rendered (rather than a disabled button or an error) — `related_node_ids`/`related_edge_ids` both empty means there is nothing to focus, so the affordance simply doesn't appear on that specific chip |
| ChangeSet card title (single operation) | "Proposed change" |
| ChangeSet card title (multiple operations) | "Proposed changes ({N})" |
| ChangeSet operation summary line format | "{Create / Update / Delete} {entity type}: {label}" e.g. "Create Location: Rita's House", "Add relationship: Dexter → WORKS_WITH → Batista" |
| ChangeSet before/after row labels | "Before" / "After" |

| ChangeSet confirm button | "Confirm" (primary-styled for create/update-only sets; destructive-styled for any set containing a delete operation) |
| ChangeSet reject button | "Reject" (outline/ghost, same visual weight as `ConfirmAdvanceModal`'s Cancel) |
| ChangeSet status — awaiting confirmation | Badge: "Awaiting confirmation" (`--warning`) |
| ChangeSet status — applied | Badge: "Applied" (`--success`, icon `CheckCircle2`) |

| Destructive confirmation (ChangeSet delete operations) | Handled entirely within the ChangeSet preview card's own Confirm/Reject controls (see rows above) — per RAG-14, the chat message itself is never confirmation, and no second nested dialog is introduced; the preview card **is** the required explicit-confirmation surface |

## Chat & Panel Architecture

> This section is this phase's primary "Visuals"/"Interaction" dimension deliverable, parallel to
> `03.1-UI-SPEC.md`'s "Graph Canvas Visual System" section — the panel-integration contract is as
> load-bearing here as the color/typography tables above.

### Resolving "Inspector/Chat mode toggle or resizable split" (Claude's discretion, resolved)

**Decision: mode toggle inside the existing `DetailPanel` Sheet, not a resizable split.**

Rationale: the existing right-workspace panel (`DetailPanel.tsx`) is a portal-based `Sheet` (`fixed`, `z-50`, not a flex-layout column) — there is no existing split-pane/flex-column architecture to make "resizable" against, and introducing a drag-resize interaction would be the first of its kind anywhere in this codebase (no precedent in `GraphControls`, `GraphLegend`, or any existing panel). A mode toggle:
- Reuses the exact Sheet component and its existing responsive desktop-width/mobile-bottom-drawer behavior (03.1's Responsive Degradation table), requiring zero new layout primitive.
- Satisfies CONTEXT.md's own phrasing exactly ("Inspector and Chat modes **or** a well-designed resizable split" — either resolves the requirement).
- Keeps "the graph remains the primary surface" trivially true — the panel's footprint never changes shape based on chat, only its content mode does.

### Mode state (independent of node/edge selection)

- The panel has two content modes: **Inspector** (existing Overview/Notes/Claims/Evidence/History tabs — byte-for-byte unchanged) and **Chat**.
- Default mode on load: **Inspector** — preserves all existing Phase 2/3/4 behavior with zero regression.
- The mode toggle (two-segment pill, "Inspector" / "Chat", same visual pattern as `EpisodeSelector`) renders in the `SheetHeader`, to the right of the existing title, whenever the panel is visible.
- Selecting a node/edge on the canvas while in **Chat** mode does **not** force-switch the panel back to Inspector (this is what "user can inspect graph and chat together" means) — the selection still visually applies on canvas (existing `.selected-dominant` glow), and the user explicitly flips the toggle if they want the Inspector detail. This is the one deliberate, documented behavior change from pre-Phase-6: previously, any node/edge tap always opened Inspector content (there was no other mode to preempt).
- Chat mode does not require a node/edge selection to render (unlike Inspector's current "Select a node to see details." placeholder, chat renders its own empty/populated state independent of canvas selection).

### Entry point: top-bar chat launcher (new, not the canvas)

- A `ChatLauncher` button lives in `AppShell`'s `topBar` slot, positioned after the existing `EpisodeSelector`, before the user/avatar/logout cluster.
- Clicking it: opens the panel (if collapsed) and switches to Chat mode in one action. Clicking again while already in Chat mode: **collapses the entire right panel** (satisfies RAG-16 "chat can collapse" — a capability Inspector mode has never needed since it's always visible today).
- This placement is deliberate: it avoids every existing canvas-overlay z-index/collision constraint (`GraphLegend` bottom-left, `GraphControls` bottom-right, Create Custom Node FAB adjacent to the legend) by not touching the canvas overlay grid at all — a persistent, always-reachable global action belongs in the app chrome, not floating on the graph.
- No unread/count badge on the launcher — not a feature requested by RAG-01..17, not invented here.

### Panel width (chat mode gets more room than Inspector — additive, not a new component)

Inspector mode's existing responsive widths are unchanged. Chat mode uses a wider variant of the same `Sheet`, since message bubbles and citation chips need more horizontal room than metadata rows:

| Breakpoint | Inspector width | Chat width |
|------------|------------------|------------|
| Desktop ≥1280px | unchanged existing | 480px |
| Desktop 1024–1279px | unchanged existing | 420px |
| Medium 768–1023px | unchanged existing (narrows) | 360px |
| Narrow <768px | bottom drawer, ~70vh (unchanged) | bottom drawer, ~75vh (slightly taller — chat needs input-field + keyboard room the Inspector's read-only tabs don't) |

### Session picker (compact, not a full session-list page)

- Rendered at the top of Chat-mode content, below the mode toggle: a compact row containing (a) a session picker control reusing the existing shadcn `Select` component (shows current session title, opens to list past sessions ordered newest-first) and (b) a "New conversation" icon button (`Plus`, `--secondary`) beside it.
- Each session-list row shows: title (or the empty-state fallback "Untitled conversation" if the backend hasn't generated one yet) + relative timestamp, plus a delete icon that appears on hover/focus (mirrors `NoteItem`'s existing hover-reveal delete-icon micro-pattern in `DetailPanel.tsx`).
- This resolves RAG-16's "session list or compact session selector" as the **compact selector** variant — a full scrolling session list is unnecessary panel real estate for a single-user prototype-scale feature and would compete with the graph for space.

### Series + episode badge

- A small `Badge` (muted styling, not accent) pinned directly below the session picker row, always visible in Chat mode: "{series title} · up to {episode code}".
- Updates immediately (no stale read) whenever watch progress changes — this is the chat-surface expression of the same authoritative-progress principle already visible in the top-bar `EpisodeSelector`.

### Message list

- Scrollable region (`scroll-area`), auto-scrolls to the newest message on send/stream, but stops auto-scrolling if the user has manually scrolled up (standard chat-UI convention, prevents fighting the user's read position during a long streamed answer).
- Assistant messages: bubble surface `--card`, left-aligned, assistant icon (`Sparkles`, `--secondary` tint) at bubble start.
- User messages: bubble surface `--elevated`, right-aligned, user's existing avatar (reused from `AppShell`'s avatar/initials logic) at bubble end.
- Streaming assistant message: text appends incrementally into the same bubble; a small pulsing cursor/indicator (reduced-motion-aware — see Accessibility below) shows at the text's trailing edge while streaming; the `Send` button area swaps to the `Stop generating` control for the duration.
- Timestamps render below each bubble in Label-role muted text, relative format (e.g. "2m ago"), full timestamp available via native `title` tooltip on hover — reusing the exact mechanism `GraphCanvas.tsx` already uses for node-label tooltips (`title` attribute, not a new tooltip component).
- Failed messages: bubble renders with a `--destructive`-accented left border (same visual language as Claims/Evidence card accents, just a different color) plus the inline error copy and Retry button from the Copywriting Contract.

### Citations

- Rendered as a row of small chips/cards directly below the assistant message bubble they support (not inline within the message text — keeps message prose clean, matches the PRD's "citation chips/cards" phrasing).
- Each chip: colored left-border accent (per the Citation Chip Accents table above), label text, and a "Show in graph" icon action.
- Clicking a citation chip's body (not the "show in graph" icon) opens the corresponding entity/claim/evidence detail — this switches the panel to Inspector mode and selects that resource (an intentional, expected mode switch, since the user explicitly asked to see detail).
- Clicking "Show in graph" specifically triggers only the graph-focus highlight (see below) — it does **not** switch panel modes, letting the user stay in Chat while looking at the canvas.

### Proposed-ChangeSet card

- Renders inline in the message flow, directly after the assistant message that proposed it (same "attached below the bubble" pattern as citations, visually distinct via the `Card` component with the status-appropriate accent from the Copywriting Contract).
- Structure top-to-bottom: title (single/plural per Copywriting Contract) → per-operation summary lines → before/after value rows (only for update operations) → affected-graph-elements list (reuses citation-chip visual style for consistency) → warnings row (if any) → destructive banner (if any delete operations) → Confirm/Reject controls (while `awaiting_confirmation`) → status badge (once resolved, replacing the controls).
- A ChangeSet card is a **terminal, immutable record** once resolved (applied/rejected/failed) — it never disappears from the chat history, consistent with the append-only Revision model it produces.

### Graph synchronization (RAG-17)

- **Graph focus (answer highlighting):** reuses the existing `.selected-dominant`/`.faded`/`.hovered` Cytoscape class mechanism and the exact `--accent` `#7C3AED` overlay glow already defined in `graphStylesheet.ts` — this is a direct instruction from `06-CONTEXT.md` ("reuse, not fork"). One documented, bounded extension: `graph_focus` may highlight **multiple** nodes/edges simultaneously (a chat answer commonly references several entities), which is not something single-click canvas selection needs today. All focused elements get the `.selected-dominant` glow treatment together; everything else gets `.faded`. This is a deliberate, explicit supersession of `03.1-UI-SPEC.md`'s Performance note that the glow "applies to at most one node at a time" — that constraint was written for continuous per-frame selection state, not a bounded, backend-size-limited `graph_focus` set (bounded by the same context-size limits RAG-05 already imposes on retrieval, typically a handful of elements) — document this supersession in code comments exactly as 03.1 documented its own hover-color supersession of Phase 2.
- The canvas fits/centers on the focused subgraph (`cy.fit()` on the focused element set, same 48px padding convention as `GraphControls`' fit-to-view) without discarding the user's zoom/pan entirely — a gentle re-frame, not a hard reset.
- A `GraphFocusIndicator` pill (new, `fixed top-4 left-4 z-[60]`, same `bg-card`/`ring-border`/`text-xs`/`rounded-md`/`shadow-sm` visual treatment as `GraphLegend`'s collapsed state) appears whenever a graph focus is active: "Highlighting {N} from chat" + an inline "Clear" text action (ghost-style, muted-foreground → foreground on hover, same micro-pattern as `NoteItem`'s inline Edit/Delete text buttons). Clicking Clear removes `.selected-dominant`/`.faded` from all elements, same effect as tapping empty canvas.
- **Applying a ChangeSet:** the canvas incrementally updates (new/changed elements appear) rather than a full destructive relayout; the newly created/changed element receives the `.selected-dominant` treatment (single-element case, since a just-created node is exactly one thing) and the canvas gently pans/fits to include it, preserving existing zoom level where possible. Character portrait images and episode-boundary filtering are unaffected (existing `graphElements.ts`/`graphStylesheet.ts` mapping logic already handles both; nothing in this phase changes those code paths).
- **Progress decreasing:** any active graph focus referencing a now-hidden node/edge is cleared immediately (same as the manual "Clear" action), any draft/awaiting-confirmation ChangeSet snapshotted above the new boundary flips to the "stale/invalidated" status/copy defined above, and chat messages above the new boundary are hidden from the message list (not deleted — matches RAG-09's hide-not-delete requirement) with no visible gap/placeholder implying something was removed (the list simply renders shorter, exactly like the existing graph canvas quietly rendering fewer nodes when progress moves backward).
