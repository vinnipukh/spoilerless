<objective>
Establish the strict, reusable Phase 03 backend contract foundation and Wave-0 test infrastructure before any Neo4j mutation routes are added. Implement D-12, D-16, D-17, and D-24 through D-27 as concrete Pydantic/error contracts, preserve D-01 through D-04 and D-23 boundaries, and create executable test homes for NOTE-01, NOTE-02, and NOTE-03. </objective>

<threat_model>
- **Spoofing / ownership classification (ASVS V4):** client payloads could claim `origin`, `series_id`, IDs, timestamps, node type on PATCH, or relationship endpoints. Mitigation: strict `extra="forbid"` request models omit server-owned fields; unit tests submit each forbidden field and require 422 validation.
- **Tampering / Cypher-shape injection (ASVS V5):** arbitrary labels, predicates, and property dictionaries could become dynamic Cypher. Mitigation: exact `StrEnum` allowlists for Character/Event/Location/Organization/Object, Character/Claim targets, and participation+character predicates; ontology-drift tests compare enum values to YAML groups and prove structural/provenance/revision values are excluded.
- **Information disclosure (ASVS V7):** default FastAPI validation and database exceptions can echo rejected values or internals. Mitigation: shared sanitized `ErrorResponse`, `http_error`, RequestValidationError handler, and retained Neo4j handlers; tests assert no input value, Cypher, credentials, or list-shaped framework detail leaks.
- **Denial of service (ASVS V5/V7):** unbounded note/label strings and free-form dictionaries can inflate validation/storage. Mitigation: conservative documented length bounds, stripped non-empty strings, no arbitrary maps, non-empty PATCH validators, and oversized-payload tests.
- No HIGH threat may remain unmitigated before this plan passes; failures block Plan 03-02.
</threat_model>
