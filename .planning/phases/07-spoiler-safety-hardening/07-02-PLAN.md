<objective>
Split the single persisted boundary field into watched_through_order and view_as_of_order with a
backward-compatible migration, implement the central visibility-policy service
(`backend/app/spoiler/policy.py`) specified in 07-01, and update the progress API contract to
expose watched_through_order / view_as_of_order / effective_view_order (D-21) while keeping
`visible_until_order` accepted for backward compatibility (PROG-04).

Purpose: this is the spine of the phase. Every later plan (07-03..07-07) consumes
`policy.effective_view_order` and the split progress record; without it, boundary semantics
would be re-derived per repository, which D-04 forbids. The migration must be lossless and
idempotent per D-07 because the live DB holds real user progress, chat snapshots, ChangeSets,
and revisions.
Output: backend/app/spoiler/policy.py, split progress persistence + API contract, effective
boundary wired into graph and chat boundary resolution, and the PROG/VIS-01 test matrix.
</objective>
