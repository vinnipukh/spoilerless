<objective>
Close the search/autocomplete and aggregate/count leak channels: hidden entities and aliases
behave exactly like nonexistent ones (SEARCH-01/D-15), and all counts/aggregates — degree,
appearance counts, relationship counts, graph-layout sizing inputs — are computed only from
boundary-visible resources with no future totals, no last-appearance, and no early final
status (SEARCH-02/D-16).

Purpose: search and counts are indirect-leak class #1 after titles: a fuzzy match or a
degree count can reveal a character or relationship the user has not reached yet. D-15 requires
indistinguishability (hidden == nonexistent) at the query level, and D-16 requires the API to
omit hidden aggregates even when the frontend would not render them.
Output: hardened SEARCH_ENTITIES_QUERY + aggregate queries, indistinguishable hidden-ID
behavior, and the D-23 search/count regression tests.
</objective>
