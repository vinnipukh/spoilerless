<objective>
Make media spoiler-safe (MEDIA-01/MEDIA-02, D-14): the backend never returns an image above
the effective boundary, the frontend renders a neutral initials fallback with leak-free alt
text for both missing and failed images, and image URLs/filenames are never user-visible text.
Failed image requests must not imply future character existence.

Purpose: character portraits are the last direct image leak channel. The existing
DetailPanel CharacterAvatar already falls back to initials for a null image_url — this plan
extends that same fallback to boundary-hidden and failed images so a user browsing at an early
boundary can never distinguish "character has no portrait" from "character not revealed yet"
(D-14).
Output: boundary-aware image filtering in the graph service, an indistinguishability-safe
avatar fallback, seed curation validation, and the D-23 media test rows.
</objective>

### UI/UX Constraints

- **Color not sole indicator** (Priority 1): the initials placeholder state (image missing/failed/hidden) must not be distinguished by color; no tint/shade variation communicates presence — the placeholder is identical in every case per D-14.
- **No emoji icons** (Priority 4): any placeholder/avatar icon uses Heroicons SVG (user icon), never emoji.
- **Accessibility** (Priority 1): the avatar img always carries an alt attribute with the safe visible label; the source link (when present) has descriptive link text ("Image source"), never the URL; icon-only elements get aria-label.
- **Reduced motion** (Priority 7): no new animations; failed-image handling must not animate a shimmer/skeleton that differs from the null-image state (a skeleton implies an image is expected → presence inference).
- **No layout shift** (Priority 1, D-14): the avatar keeps its fixed aspect box across null/failed/hidden states so the detail panel does not reflow.
- **Demo/offline guards**: the avatar fallback must also cover the case where the backend is unreachable — same initials placeholder, no crash (optional chaining on node.image_url).
- **Async data null-safety**: render-time accesses use optional chaining (node?.image_url) per the ui-ux-review embedding checklist.
- **React 19 test workaround**: DetailPanel tests use createRoot + flushSync (setup.ts polyfill); JSX test files stay .tsx.
