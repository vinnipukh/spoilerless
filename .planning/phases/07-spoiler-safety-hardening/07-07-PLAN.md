<objective>
Integrate every chat/GraphRAG and graph-editing path with the effective boundary: retrieval,
history, citations, graph focus, and speculation all run at effective_view_order (CHAT-01/02/03,
D-12); new user content and ChangeSets derive visible_from_order from the current view context
and stale later-boundary ChangeSets fail closed (EDIT-01/02, D-13).

Purpose: chat and editing are the highest-value surfaces — they combine LLM generation,
persisted snapshots, and graph mutations. D-12 requires the LLM to be structurally unable to
raise the boundary (it receives only effective-boundary context), and D-13 requires the
visibility of user-created content to come from the view context, never from the model.
Output: effective-boundary chat pipeline + snapshot semantics, view-scoped ChangeSet/note
visibility derivation, stale-ChangeSet fail-closed behavior, and the D-23 chat/editing test
matrix.
</objective>

### UI/UX Constraints

- **Color not sole indicator** (Priority 1): message visibility state (hidden vs shown) is never communicated via color; hidden messages are simply absent (server-filtered), and any boundary indicator uses text.
- **No emoji icons** (Priority 4): any new focus/clear affordance uses Heroicons SVG.
- **Accessibility** (Priority 1): when a focus is cleared due to a boundary change, the GraphFocusIndicator disappears cleanly (no focus trap); message list updates must not move keyboard focus unexpectedly.
- **Reduced motion** (Priority 7): message show/hide on boundary change is appear/disappear, no animation.
- **No layout shift** (Priority 1): when messages are filtered out on an earlier view, the message list reflows without a jarring jump — reserve consistent spacing.
- **Stale closure avoidance**: any effect keyed on the effective boundary that reads chat/focus state must use the ref-forwarded callback pattern.
- **Async data null-safety**: render-time accesses to session/message objects use optional chaining (session?.messages).
- **React 19 test workaround**: App/useChatMessages tests use createRoot + flushSync; JSX test files stay .tsx.
