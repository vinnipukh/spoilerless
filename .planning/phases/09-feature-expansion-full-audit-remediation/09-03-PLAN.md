<objective>
Close the audit's most dangerous findings (#1-#4, #11, #33/#34, #49-#51) in one
coherent subsystem: the WRITE PATH. Every mutation endpoint gets an
authenticated, correctly-scoped owner; user-content records carry owner
user_id and are owner-only to mutate; direct creates stamp created_by; the two
create paths share ONE visibility-derivation rule; candidate approve/reject
return the revision id that was actually persisted; every logged revision
records the actor; and ChangeSet revert keeps both revision links. This is the
"lock the write surface" survival-order item from PROBLEMS.md.

Purpose: Transform 14 anonymous write operations into owned, attributable,
consistently-derived mutations — the precondition for a public deployment
where user content cannot be vandalized or poisoned.
Output: All mutation routes auth-gated; ownership + attribution + single
visibility rule + honest revision ids, with scratch-scoped integration tests.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Anonymous client <-> mutation routes | Previously open; now must cross authentication |
| User A <-> user B's content records | Owner-scoping boundary; cross-owner mutation must fail |
| Route layer <-> repository layer | api/candidates.py previously reached into repo._db (#41-style breach) — keep repository boundary |
| ChangeSet apply/revert <-> revision history | Dual-link preservation |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-09-03-01 | Tampering | Anonymous mutations (#1-#3, #11) | critical | mitigate | CurrentUserDependency on every mutation route; 401 tests per route; admin gates kept on approve/revert |
| T-09-03-02 | Elevation of Privilege | Cross-owner update/delete (#4) | high | mitigate | Owner-scoped update/delete with user_id; admin bypass explicit; 403/404 tests |
