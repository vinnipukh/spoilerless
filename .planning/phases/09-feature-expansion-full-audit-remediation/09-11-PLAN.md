<objective>
Ship the relationship finder (FEAT-06) and Markdown export (FEAT-05) as one
plan because they share the same backend file (api/graph.py), the same
selection/framing affordances in GraphCanvas, and the same "expose an existing
allowlisted seam through a direct route" pattern (RESEARCH Pattern 3). The path
route calls the existing find_path executor with the server-resolved boundary;
the export route renders Markdown from the SAME filtered read path (D-11:
Markdown only, zero new deps).

Purpose: Give users an explicit "how are X and Y connected" action and a
portable knowledge export, without duplicating any retrieval or filtering
logic.
Output: Two backend routes + two frontend feature surfaces, contract-tested.
</objective>
